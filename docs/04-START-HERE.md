# START-HERE：WhyCode 开发指南

> 本文维护项目导览、工作流程、异步资源规范和文档地图。通用代码质量见 [AGENTS.md](../AGENTS.md)；环境、验证和 PR 流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 1. 项目是什么

WhyCode 是一款 Windows 优先的通用桌面 Agent，尤其擅长代码与工程任务，也支持研究、写作、规划、附件和 Office 制品。技术形态为 Electron + React + TypeScript monorepo；核心能力包括多模型接入、安全工具执行、持久会话、上下文压缩、TaskPlan、多 Agent 协商和通用子代理。

项目已经开源，仍处于开发阶段。

## 2. 确定当前事实

产品范围看文档一，实现机制看文档二，精确协议看文档三和对应代码；未竟事项、验证边界和阻塞只看文档五。代码与文档不一致时，结合用户要求、测试和实际行为定位差异，不能直接把缺陷当作新契约。完成日期、commit、测试数量和验收过程留在 Git 历史。

安装与运行见 CONTRIBUTING；修改 Core 后需重启 dev，不能假定 Electron Main 会热载。API key 只由 Main 通过 `safeStorage` 保存，Renderer 不得取回明文。

## 4. 工作规则（必须遵守）

1. **开工**：检查 Git 状态和文档五，按任务读取相关文档、实现和测试；需要追溯时查看相关文件历史。基于已同步且包含现有有效工作的 main 切分支，或继续适合当前任务的功能分支，保留无关改动。
2. **开发**：遵守 [AGENTS.md](../AGENTS.md) 的开发约束，按任务读取文档二的模块机制与 Renderer 基线。新能力或架构决策先调研，优先参考 Claude Code、开源 Codex CLI，并用 DSH 等相关实现交叉验证；普通修复先查本仓库的契约和测试，不重复研究无关项目。不确定事实先查证；仍缺产品决策或必要信息时向用户澄清，不能凭空补全。
3. **专项工作流**：只在任务命中时读取对应项目 Skill。新增、替换、退役或审核模型，以及同步 CLIProxyAPI 路由时，必须先完整读取 `.agents/skills/whycode-model-catalog/SKILL.md`。
4. **收工（每次任务结束前，缺一不可）**：
   - 只把仍未完成、待验证、受阻和下一步写入 `05-暂存区便签.md`；已经完成的过程不要留下；
   - 新增或改变了稳定产品事实时更新文档一，改变架构/生命周期时更新文档二，改变模型或协议契约时更新文档三；
   - 只检查本次影响到的文档与引用，保持单一权威来源，不为“显得有更新”而改文档；
   - 阶段性停止且存在明确的未来方向时，把非承诺方向、触发条件和前置依赖写入文档一，不伪装成进行中事项；
   - 按 CONTRIBUTING 选择本地验证并整理提交，报告实际结果及未测边界。
5. **git**：推送、验收合并、分支清理及提交内容遵守 [CONTRIBUTING](../CONTRIBUTING.md)。
6. **文档写入原则**：先判断归属再写。同一稳定事实只保留一个详细来源，其它文档只链接；当前视角写“现在是什么”，不记录“当时怎么改”；Git 历史承担完成历史，便签承担短期交接。

## 5. 异步、错误与资源

修改异步、取消、进程、浏览器或清理逻辑时，结合所属模块的生命周期契约遵守以下要求：

- **明确所有者**：资源必须有明确所有者、取消与释放路径，区分会话、turn、窗口、应用与共享连接；UI 挂载或当前选中会话不能替代后台生命周期。
- **按需捕获**：尽量避免使用 `try`/`catch`，只在能恢复、转换错误或收束异步失败的所属边界捕获；保留必要的 `finally` 清理，不遗漏取消和异步拒绝的处理。用明确类型或稳定状态区分预期错误，保留 `cause`，不根据展示文案分支，不吞错后报成功。
- **明确失败效果**：区分未发生、部分完成、已提交和结果未知，明确处理者与重试条件；无法确认状态安全时停止依赖操作并如实反馈。重试仅用于可安全重复的操作，必须可取消且有明确预算。
- **等待退出再释放**：abort、kill 或关闭请求不等于工作已停止。按依赖顺序阻止迟到回调发布状态，取消并等待任务退出，再释放资源；保留各自承担取消、回滚和终态结算的必要机制。
- **提交后发布**：成功提交后才发布对应事实，UI、查询和恢复使用同一来源；快照与实时事件在明确边界接续，临时进度不得伪装为已提交结果。
- **完整清理**：WhyCode 产物须有明确归属、存储位置、生命周期和用户可用的完整清理入口，创建与清理一并设计和验证，覆盖本地与远端的目录、组件、同步副本、临时文件及缓存。清理前说明删除与保留范围，先停止写入并释放资源，再删除所属产物；不得清理用户原有文件、其它任务资源或未授权的共享数据。部分失败如实提示并允许重试，验证实际状态与资源释放，不能只检查返回成功。
