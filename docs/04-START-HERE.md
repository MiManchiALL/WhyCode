## 1. 项目是什么

WhyCode：Windows 优先的通用桌面 AI Agent（Electron + React + TypeScript monorepo），尤其擅长代码编写、代码理解、调试及其他编程相关任务，同时处理生活、写作、规划和知识问答等通用任务；支持 OpenAI/Anthropic/Google Gemini/DeepSeek/智谱/小米 MiMo，核心特色是多 Agent 协商决策（Main/B/C 投票共识）。代码在 `E:\Agent\WhyCode`，参考用 Claude Code 源码在 `E:\Agent\Claude Code`（只可阅读借鉴，**禁止复制其源码、禁止提交进本仓库**）。

- **连接收口与 CLIProxyAPI**：模型设置只保留内置厂商、CLIProxyAPI、网页搜索；任意协议、手填模型名、连接探测、未知型号画像和模型名后缀链路已删除。旧 v3 自定义配置只在一次性迁移中提取 `custom:<id> → 原模型名` 供退役历史显示，密钥与旧连接随后从配置移除，不形成运行时兼容逻辑。CLIProxyAPI 只保存一套 Base URL/key 和审核过的型号选择；活动连接使用 `cliproxyapi:<WhyCode 型号 ID>`，下拉框显示“（CLIProxyAPI）”，可与厂商连接并存。
- **CLIProxyAPI 独立兼容目录**：`cli-proxy-models.ts` 维护“同一真实型号”的审核路由及该路由明确公布的最小能力约束，当前实例鉴权后的标准 `/v1/models` 只负责确认候选 ID 在该账号是否可用。启动、打开设置和保存时都读取一次目录；`modelRoutes` 保存该实例当前公布的全部审核路由，`modelIds` 只保存用户明确启用项。成功同步会删除目录中已经消失的旧选择，目录请求失败则保留上次配置；设置页只显示本次实例实际公布的候选，未启用但已公布的型号仍可勾选。当前 Gemini 3.7 候选来自 CLIProxyAPI v7.2.132 内嵌目录提交 `7ea9c67` 的精确 Antigravity 路由 `gemini-3.7-flash-high`；旧 `gemini-3.6-flash-high` 已随厂商型号退役从活动兼容目录删除。WhyCode 不固化某次实例目录状态，始终按当前目录求交集：实例未公布时隐藏并清理失效选择，重新公布后允许用户启用。路由名中的 `-high` 是 CLIProxyAPI 官方 ID，不是 WhyCode 追加的推理后缀；用户档位仍通过请求体传递。近似名、旧版本和其它未审核 alias 不映射到 3.7。
- **CLIProxyAPI 有效画像**：内置目录继续保存厂商官方画像；CLI 连接在解析边界用一个函数把厂商画像与已审核路由约束合成，不复制第二份完整目录。数值上限取较小值、推理档位取交集、明确布尔限制不能被补回；缺失字段只有在同型号身份及能力透传已经审核时才继承。当前 Claude Sonnet 4.6 CLI 路由为 200k/64k；Gemini 3.7 High 为 1,048,576/65,536，只开放 low/medium/high 且默认 high；GPT-5.6 Sol/Terra/Luna 为 372k/128k 且只开放 low/medium/high/xhigh/max，Sol 默认 low、Terra/Luna 默认 medium；GPT-5.5 为 272k/128k 且只开放 low/medium/high/xhigh。官方直连画像不受影响。设置页、顶部能力、Provider 和自动压缩共用这份有效画像；Codex `ultra` 属于带自动任务委派的产品执行模式，不作为 WhyCode 通用推理档位。
- **统一推理强度**：顶栏只按当前连接的有效画像展示已验证档位；内部 `default` 不覆盖厂商/连接默认，但界面直接显示该连接记录的默认档位，不再同时出现“默认（高）/高”。同一真实型号经官方端点和 CLIProxyAPI 接入时可以有不同档位及默认值；例如官方 GPT-5.6 可关闭推理，CLI 路由不可关闭。型号与强度作为同一会话事实持久化，切模型时强度回 default，恢复时不再受支持的旧档位归一到当前连接 default。Provider 根据实际 Responses、OpenAI Chat 兼容或 Anthropic Messages 协议传参；内置 Base URL 中转和 CLIProxyAPI 都不靠模型名括号后缀。已确认的 GPT 画像通过 SDK `forceReasoning` 防止代理路由别名被误判成非推理模型；没有已验证可选档位的型号固定灰色“推理：默认”。
- **网页研究能力**：普通 Main 现在拥有厂商无关 `WebSearch/WebFetch/WebFind`，默认受管工作区会话同样可用，讨论、M1/B/C 和协议回合物理移除。WebSearch 可在设置中选择 Perplexity 或 Tavily，始终返回同一有界摘要、日期与 `[Sx]` 可点击来源契约；`query` 保持字符串主路径，也可用 2～4 个字符串数组批量搜索，单次总计最多 20 条。Perplexity 使用一个 multi-query 请求；Tavily 因官方端点只接收字符串而在同一工具调用内有界并发。WebFetch 只读取无需登录或服务身份的公开静态页面或远程 PDF；普通已知 URL 且未明确要求私有、登录或账号数据时先尝试公开读取，失败或明确需要授权数据时再走 ToolSearch；需要发现来源而非读取已知 URL 时才用 WebSearch。该路由只修改稳定工具描述，不引入 GitHub 特判、MCP 状态或工具数组改写。未取消的 WebFetch 失败结果会追加一句精简的可选 ToolSearch 提示，用户取消不追加。网络留在 Main，HTML 清洗/Readability/Markdown 在一次性 Utility Process，文本结果提供稳定行号、分页、可点击来源和 `Lx-Ly`；远程 PDF 直接复用现有附件事务保存到会话，返回来源和附件 ID，后续统一由 `ReadPdf` 按页读取，不再生成 Web 专属有限正文或行号。`offset/limit` 均可省略且只对文本有效，WebFind 也只查同一会话文本缓存。网页与 PDF 始终标记为不可信资料，完整链路不增加第二次模型调用。
- **Tavily 后端边界**：设置页分别保存两家 key，并用一个活动后端字段选择；旧 Perplexity 配置无需迁移，清除当前 key 时只回退到另一已配置后端。Tavily 固定官方 `/search` 与 Bearer 鉴权；用户只可选 basic/advanced，默认 basic，advanced 明示消耗 2 credits。请求开启自动参数但显式固定深度、结果数和内容边界，不指定 topic，让服务选择 general/news/finance；answer/raw content/images 继续关闭，hour 映射为 day。适配器按 score 相对降序且不设固定阈值；Core 对两家结果统一按规范化 URL 去重。批量普通失败保留其它成功结果并列出失败查询，全部失败、用户取消或统一超时才整体报错；无隐藏重试。适配器不复制 Core 工具、审批、最终格式或错误控制流，与 Perplexity 共用固定传输、响应限长和脱敏边界。
- **会话删除与确认**：历史会话删除过去与当前会话删除共用全局 `runtimeBusy`，目录清理期间会无故禁用当前模型下拉框、输入框和发送。现删除仍全局单飞，恢复、新建、重复删除和切工作文件夹仍互斥；但只有删除当前会话才阻塞当前运行时，历史删除可与当前输入、附件、模型切换和 Agent 运行并行。Renderer 以删除前的 Main `runtimeSnapshot.sessionId` 判定当前会话，不依赖可能过期的历史列表。Local 删除顺序为持久 delete-only 标记、命令/临时数据、退役显示名引用收尾、会话事实源，绝不触碰用户工作文件夹；Worktree 删除在命令停止和运行体/租约释放后、会话事实源删除前显式移除受管 Worktree，失败则保留 delete-only 入口供重试。附件、检查点和 transcript 均在会话目录内随事实源删除。Windows 上两种删除后“按钮可点但输入框、模型和推理下拉框失效”的共同根因是唯一的原生 `window.confirm` 破坏 Electron 表单焦点；确认现收回历史行内，不增加 focus 补偿、计时器或第二套删除控制流，Main 生命周期保持不变。
- **多对话并行运行**：Main 用 `SessionRuntimeRegistry` 分离“当前选中”与“仍在执行”。每个 `DesktopSessionRuntime` 独占 AgentSession、Journal、MCP/WebFetch 缓存、审批、项目/模型/推理、协商、路由闸门、附件准备和瞬时时间线；权限判定仍由各运行体执行，但用户选择的权限档是全局偏好，切档会同步应用到全部已加载运行体，新建或恢复运行体也采用该偏好，审批记忆仍保持会话隔离。IPC 命令、事件、快照及 PDF 打开都携带 runtimeId，后台事件不能污染当前对话。最多同时运行 8 个 Agent；新根输入在任何异步准备前通过目标运行体既有路由闸门原子预留名额，并在到达 FIFO 队首后按真实执行态判定 root/steering，避免并发 IPC 超限或前一输入失败后误分类。切走不终止运行，历史面板显示后台运行状态；“等待操作”只用于真实审批或待回答问题，普通错误结束仍保留时间线错误但按可恢复的已结束会话展示。历史列表统一使用仓库中全部已打开 Journal 的实时 metadata；后台会话不会因“不是当前选中项”而从磁盘重开，也不会在 RenderOffice 等附件提交窗口触发恢复期清理，因此“后台运行”与“仅可删除”不会再由同一次刷新矛盾地产生。会话可随时切回并从“稳定事件 + 当前未提交 step + 同边界事件游标”的原子快照继续；切换、恢复或重连不向聊天时间线合成蓝色提示。非选中且空闲的运行体保留 30 分钟再关闭 AgentSession/MCP/WebFetch 并释放 Journal 内存，重新选中会取消卸载；后台运行体从真正转为空闲时开始计时，后续仍可从 JSONL 重建。宿主管理的后台命令仍按 sessionId 继续运行。未发送的已持久会话输入草稿按 sessionId 暂存，删除会话同步清除其草稿和事件缓冲；没有历史入口的空白草稿切走即释放。

  Local 模式中，同一规范项目路径的 edit/execute 与检查点恢复通过宿主 FIFO 覆盖“最新硬边界重查 → 检查点 → 执行 → 收尾”，不同项目可并行；权限判定、同一步审批聚合和用户等待在副作用锁外完成，不让审批卡占住同项目写队列。路径先解析真实路径并在 Windows 统一大小写，避免别名绕过。截图使用独立全局串行键，防止多个会话交错隐藏/恢复窗口，只读操作仍可并发。默认等待的有限 `StartCommand` 始终留在工具临界区；只有 `detach=true` 的长驻进程在工具返回后继续作为显式不可回滚宿主任务，Local 不提供进程级隔离。需要隔离时可在首条消息前点路径并选择 Worktree。连接配置等全局事实源在任一对话工作时拒绝修改，MCP 变化仍在运行体重建时生效。
- **显式 Worktree 工作区**：当前会话 schema v11 继续用 `WorkspaceBinding` 作为唯一工作区事实源，并要求 `local|worktree|managed` 三种绑定完整可判别；开发期 v10 及更早 schema 不迁移。Worktree 只在 Git 仓库已有 commit 时可选；选择目录后列出当前仓库的本地起始分支，当前分支默认置顶，源目录为 detached HEAD 时则把该提交置顶。用户选择只锁定 `baseRef + expectedBaseCommit`，Main 创建前重新解析所选引用；目标分支删除或推进会拒绝，无关的当前分支变化不误伤。实际创建始终使用所选精确 commit 的 detached HEAD，不占用所选分支。Local 脏改动不静默复制；`.worktreeinclude` 只能带入明确列出的 ignored 普通文件/目录，并拒绝导航、盘符/尾随点空格、通配符、符号链接和覆盖。受管目录位于 `~/.whycode/worktrees/<仓库指纹>/<ID>`，manifest v2 用 `sessionIds[]` 显式记录 Fork 共享引用；运行时租约和 Git 登记共同校验，普通恢复只能补齐完全无引用的 session-start/manifest 窄崩溃窗口，已有其它会话引用时 fail-closed。递归删除前还会重新校验普通目录与 realpath，路径被符号链接/目录联接替换时保留现场。Windows 下使用临时 Git 参数忽略文件系统无法表达的 executable bit，不改写用户 `core.filemode`；启动只回收没有会话事实引用的干净草稿，有真实改动、detached 提交或窄崩溃窗口会话引用时继续保留；最后一个引用解除后才移除 Worktree，最后一个子 Worktree 删除后同步非递归移除空的仓库指纹目录。Worktree 的项目指令、Skill 目录、MCP、权限、工具/命令、宿主写队列、附件与检查点全部跟随有效子目录；B/C 仍只写项目外 scratch。顶部/历史明确标记模式，面板提供状态、变更、tracked diff、打开目录与创建分支，不自动 commit/merge。只有无文件变化、无未建分支 detached 提交的空白草稿才自动清理，已建立会话默认保留；删除或显式丢弃才按验证后的所有权清理，已建分支及其提交保留，未建分支提交会先得到明确警告。
- **Worktree 创建时序**：选择模式与分支时，Main 只校验请求并把 `pending-worktree` 放入运行时快照；此时没有执行目录、Git 登记、所有权清单或 JSONL。第一条消息先经过模型/连接校验，再在 `ensureSession` 单飞事务中重新解析精确基线、创建并绑定 Worktree，之后才读取会话级自定义 System、写 `session-start` 和构造 AgentSession。Main 的命令结果把真实绑定同步给 Renderer；选择阶段顶部显示“Worktree · 待创建”，不能提前打开不存在的状态面板。空白草稿切走立即释放；若实际创建后后续初始化失败，干净无会话草稿仍由既有所有权与 Git 状态校验安全回收。
- **每会话默认工作区**：点击“＋新会话”直接得到 `pending-managed` 草稿，不先弹目录模式框；首条消息通过模型/连接校验后，`ManagedWorkspaceManager` 才在 `Documents/WhyCode Workspace/<runtime UUID>` 创建独占普通目录、写外置所有权记录并绑定 sessionId。首条消息前可从输入框上沿选择项目：非 Git 直接 Local，Git 先进入 Local，并用相邻的启动模式与基线分支 Radix 菜单按需切换 Worktree。删除 managed 会话先停命令、释放运行体，再以绑定、manifest、realpath 和非链接校验删除其目录与记录；Local 用户目录不删除，Worktree 继续走 Git 所有权流程。应用启动先完成孤儿 managed 清理，再创建运行时，避免清理与新建竞态；默认根只作为容器，子目录清空后保留根本身。

## 5. 开发质量红线（所有模型必须遵守）

### 5.1 通用代码红线

1. **先找后写**：写新函数/组件前先搜同类实现，能复用/扩展就不新建；发现重复立即合并。
2. **不为未来写代码**：只实现当前模块需要的；「以后可能用」的抽象、配置项、参数一律不写（接口预留仅限文档明确要求的，如宠物事件）。
3. **删胜于加**：改动导致旧代码无用时同步删除；禁止注释掉留着、禁止 `xxx-old`/`xxx-v2` 并存。
4. **行数是审查触发线，不是机械上限**（用户定案 2026-07-10）：单文件约 300 行、单函数约 50 行时重点检查职责与可读性；能拆且更清晰就拆，内聚逻辑拆开反而增加跳转时可保留。禁止为了凑行数做碎片化拆分，也禁止借此向大文件无节制堆逻辑。
5. **依赖最小，不重复造轮子**：新增 npm 包必须先说明为什么现有依赖做不到，并记入便签，但对已有成熟方案的通用基础能力，不得为了减少依赖自行实现，除非能说明自研在安全性、维护成本和测试覆盖上更可控。
6. **注释只写「为什么」**：不写「这行在做什么」的翻译式注释，不留调试残留（console.log 等）。
7. **每次收工自查**：本次改动有没有让任何文件变得更难读？有就当场清理，不留给下一个模型。
8. **治因不治症，禁止补丁式堆叠**：修改前先定位根因和现有代码的职责边界，默认直接修正产生问题的逻辑；不得用外围特判、重复校验、兜底或补偿流程掩盖本可修复的根因。优先通过复用、调整或删除现有代码解决；现有数据与控制流程足够时，不新增中间结构、状态字段、计数器、缓存、标志位或抽象层。确因兼容性、外部依赖、线上止血或职责边界无法直接修复根因时，可以采用补丁方案，但必须说明原因、适用边界和后续处理方式，且不得形成与现有实现并行的第二套业务逻辑。
9. **开发期旧对话不做兼容**（用户定案 2026-07-30）：当前尚在开发，已有测试/开发会话可以随实现演进失效；禁止为了继续读取旧对话而增加 schema 默认值、迁移器、旧事件分支、双格式解析或展示兜底。只有用户以后对已发布数据另行明确提出兼容要求时，才重新设计迁移边界。

### 5.2 前端开发附加红线（涉及 Renderer/UI 时必须遵守）

1. **唯一基线**：动工前完整阅读文档二 §5.14；信息架构、视觉参数和组件用法只在那里维护，不在需求或便签复制第二份。
2. **复用现有原语**：优先使用既有 Radix 菜单、选择器、纸贴 tokens 与布局组件；禁止原生 `select`、一次性下拉框、平行弹窗体系或组件内散落同义尺寸。
3. **克制分层**：以 Codex 式极简为主体，纸贴只表达明确分组；工具卡、正文和主时间线不得为了统一风格被装饰化，不能靠高饱和颜色或过量留白制造层次。
4. **性能边界**：手绘效果只能使用可缓存静态资源和背景伪元素；禁止 turbulence、实时 filter、Canvas/逐帧 JS、非状态反馈型持续动画或对正文容器整体变换。纸贴 hover 只能复用文档二 §5.14 的全局有界 transition，不得在组件内另写变体或常驻 `will-change`。
5. **响应式与可用性**：每次界面改动都要检查窄窗口、长文本、焦点、键盘/IME、菜单清晰度和内容溢出；自动收起不得覆盖用户主动开合状态，关键模型/任务状态必须保持可见。
6. **不越过前端职责**：纯界面任务不得顺带改 Core、IPC、JSONL、会话 schema 或权限语义；确有需要时先单独设计并取得用户确认。旧组件失去职责后同步删除，不保留旧 UI、双路径或开发期兼容分支。

## 6. 模型目录更新规范（新增、替换或退役模型时必须遵守）

1. **先取得一手契约，再改厂商目录**：以厂商当前官方模型页、API/迁移/弃用文档为主，记录核对日期；至少确认正式 API ID、稳定/预览状态和生命周期、输入输出模态、流式与工具调用、结构化输出、上下文/最大输出、缓存、推理内容形态、可调推理档位及默认值、协议端点和必须回传的 provider metadata。还要核对当前 AI SDK 能否无损表达这些字段；官方没有证明的能力一律不猜，不因名称相近继承。
2. **先明确“保留还是替换”**：保留表示新旧型号各有独立画像和测试；替换表示从活动目录、注册表、默认配置、设置页、测试和正式文档中完整删除旧型号，不保留跨版本别名、隐藏兼容分支或第二套 providerOptions。厂商迁移建议不等于 WhyCode 自动迁移：除非用户明确要求，旧会话的 `modelId` 不重写，对话和附件不删除。
3. **退役历史可读、不可静默换模**：同一当前可恢复 schema 内，历史会话即使引用已退役型号也必须能够打开并完整展示；顶栏保留该会话最后使用的原型号名并以红色“已停止支持”显示，下拉框不伪造选中项。发送前由 Main 的当前模型解析边界明确要求用户主动选择现有型号。禁止偷偷回退默认模型、改写 JSONL，或把旧版本 ID 当作新版本别名；用户明确切换后只更新当前会话，不能连带改写其它历史会话。退役显示名属于引用型历史元数据：只为最后仍选择该型号的会话保留；会话删除必须在事实源删除前按其余会话引用清理，不能留下孤儿配置，也不能误删其它会话仍需的名称。
4. **保持单一事实源并同步删除旧代码**：`providers/catalog.ts` 只维护厂商型号的精确 ID 与官方固有画像，`registry.ts` 只维护协议工厂；UI、Main 和 Provider 不复制能力表。CLIProxyAPI 只在既有兼容目录中保存每条审核路由的最小约束，由唯一合成函数产生有效画像，不另建完整 CLI 模型注册表。不得按版本号散落 `if/else`、保留任意型号兜底、复制整份能力对象或增加平行 providerOptions。更新造成的常量、类型、IPC、配置字段、测试夹具和说明失效时同步删除；一次性旧配置迁移只能保留历史显示所需的最小数据，不能复活旧运行时逻辑。
5. **厂商目录与 CLIProxyAPI 分阶段更新**：阶段 A 新增、替换或退役厂商型号时，先按第 1～4 条完成并记录完整厂商画像，只更新内置厂商，`cli-proxy-models.ts` 保持不动；CLIProxyAPI 尚无权威同型号路由契约时，该型号不得出现在 CLIProxyAPI 可启用列表。阶段 B 只有用户明确说明“内置厂商已更新，现在更新 CLIProxyAPI 的某型号”时才开始：若既有厂商画像仍是当前契约，直接复用，只补查当前 CLIProxyAPI 发布版及源码、`internal/registry/model_updater.go` 指向的官方远程目录与对应提交、内嵌离线目录、Provider/客户端专用元数据（如 Codex client models）、`-local-model` 等启动边界、OAuth 别名、入口协议、推理参数翻译和账号限制；厂商契约已变化时只刷新受影响事实。候选必须由官方内嵌或远程目录证明指向同一真实型号，再与目标实例鉴权后的标准 `/v1/models` 求交集；后者通常只可靠提供 ID 和可用性，不能据此动态生成画像。不能只搜二进制内嵌表，也不能把路由名称、可响应或模型自述单独当作型号身份证据。路由名可以不同，但旧版、近似名和未审核 alias 不能冒充新型号。CLIProxyAPI 的常规同步范围只包括 OpenAI、Anthropic 与 Gemini，并且每次只更新用户当轮明确点名的其中型号；同一请求还点名了其它厂商的内置型号，不代表它也应接入 CLIProxyAPI。
6. **CLI 路由能力必须按字段合成，不能整份继承或普通覆盖**：型号身份、官方说明及知识边界以厂商画像为准；上下文/输出取厂商与路由上限的较小值，推理档位取交集，路由明确给出的闭集缺项不能从厂商补回，显式 `false` 优先且 CLI 数据不得反向开启厂商画像未验证的能力。缺失只表示未知：只有已审核同型号且确认该字段由路由完整透传时才能继承，否则关闭或暂不接入。路由独立默认值必须记录；模型名中的 low/high 可以表示路由默认，但不能代替请求体档位。同一 ID 若可能由多个 OAuth Provider 提供而标准 `/models` 无法区分，取所有可能路由的安全交集，无法得到可靠交集时拆分或不开放。`supported_parameters`、输入模态和推理档位是不同字段，不能互相推断；Codex `ultra` 等包含运行时编排语义的产品模式不得冒充通用 API 推理强度。审核结果固定随 WhyCode 发布，应用启动时不从可变 GitHub 目录拼装画像。
7. **推理强度按“会话选择 → 当前连接有效画像 → 协议翻译”处理**：内置目录逐型号声明厂商档位和默认值，CLI 连接再按第 6 条收窄；UI 只展示当前连接真实档位，内部 `default` 映射为该连接默认显示，没有可验证档位时固定灰色“推理：默认”。选择与连接限定 `modelId` 一起属于会话事实，切换模型时回到 default；模型或路由升级后，旧选择若不在新闭集中，恢复和发送边界归一到当前连接 default，绝不能继续发送非法值。Provider 按实际协议翻译为 Responses `reasoning.effort`、OpenAI Chat `reasoning_effort`、Anthropic adaptive thinking + `output_config.effort`；内置中转和 CLIProxyAPI 共用这条链路，禁止通过 UI 或模型名括号后缀控制。
8. **更新必须验证完整链路**：至少覆盖厂商目录/注册表与设置快照、CLIProxyAPI 审核候选、逐路由能力约束和目标实例 `/models` 解析、官方与 CLI 同型号互不污染、上下文上限进入自动压缩、档位交集/默认值/非法旧选择归一、实际路由 ID和三种协议请求线格式、推理签名/摘要的后续工具轮次回传、图片/工具/结构化输出边界、只显示已配置连接、模型切换与重启恢复、旧配置迁移、已退役模型历史打开/切换/删除和发送拦截；随后运行受影响测试、全仓 typecheck、生产 build、`git diff --check` 和密钥/旧型号/死代码检查。能做真实端点烟测时关闭自动重试并把结论记入便签；未做或因无 key 不能做必须如实标明，不能把离线适配器测试写成真实模型验收。
