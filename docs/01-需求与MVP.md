# WhyCode 产品需求与 MVP 范围

> 本文只回答“WhyCode 要为用户提供什么结果、当前范围到哪里”。实现机制归 `02-技术栈与架构.md`，模型与工具的精确契约归 `03-Agent与协议契约.md`，开发规则归 `04-START-HERE.md`，当前未竟事项归 `05-暂存区便签.md`。完成记录由 Git 历史承担。

## 1. 产品定位

WhyCode 是一款 Windows 优先的通用桌面 Agent。它尤其擅长代码编写、代码理解、调试和工程交付，也能完成资料研究、写作、规划、知识问答与 Office 制品等通用任务。

产品的核心价值不是“聊天窗口加工具”，而是让用户能够把一个真实目标交给 Agent，并在清晰的权限、工作区、会话和恢复边界内持续推进到可验证结果。

WhyCode 支持多个模型厂商与兼容网关，并提供两类多 Agent 能力：

- **协商决策**：Main、B、C 围绕高风险或明确要求协商的问题独立分析、评审和投票，最后仍由 Main 执行。
- **子代理协作**：Main 可把边界明确的探索、审查或实现任务交给独立子代理并行推进，再吸收其终态结果。

## 2. 产品原则

1. **结果优先**：Agent 应持续读取、验证、修改和检查，直到目标完成或出现真正需要用户决定的阻塞。
2. **证据优先**：可能变化、当前上下文无法可靠确认或存在实质不确定性的事实，应先用可用只读工具核实；模型记忆不能替代需要时效性或出处的证据。
3. **边界明确**：权限、项目目录、会话临时目录、交付目录、后台任务和子代理归属都必须可解释、可审计。
4. **用户掌控**：用户可插话、停止、恢复、回滚、Fork、切换模型和调整权限；系统不得用隐式迁移或静默回退替用户做关键决定。
5. **上下文连续**：长任务、压缩、重启、后台唤醒与 Fork 后都应保留完成目标所需的真实状态，同时避免无界内存和上下文增长。
6. **界面克制**：核心信息持续可见，执行过程可展开，最终结果易读；动画和装饰只用于状态反馈，不能妨碍流畅性。
7. **开发期不背负旧格式**：项目仍处于开发阶段，旧测试会话可以随 schema 演进失效；除非用户另行明确要求，不为旧对话增加兼容分支。

## 3. 当前产品范围

| 能力域 | 用户可获得的结果 | 当前边界 |
|---|---|---|
| Agent 执行 | Main 可连续调用文件、搜索、命令、网页、MCP、附件与制品工具，最终给出完整交付 | 分析、解释、审查或诊断请求不会自动改文件；危险或越界操作仍受权限控制 |
| 工作区 | 支持本地项目、受管默认工作区和受管 Git Worktree；每个会话有独立 scratch；设置可管理删除会话后保留的工作区，清理期间仍可操作设置与会话 | 删除会话始终保留本地项目；WhyCode 创建的非空工作目录默认保留，由用户明确清理。共享目录保护与生命周期见文档二 §7.2 |
| 权限与审批 | 提供只读、默认、自动编辑和全自动等模式，工具执行前统一判定 | 模式只改变授权，不改变事实边界；只读不能通过审批或命令绕过 |
| 会话 | JSONL 持久化用户可见过程、模型上下文和运行状态；支持恢复、删除、原位编辑与 Fork | Fork 只发生在完整完成边界；源会话不变，临时授权与运行中任务不继承 |
| 临时侧对话 | 空闲时可用 BTW 开始不写入 Main 上下文的题外问答，并用 BBTW 连续追问，最多三轮 | 侧问答在时间线可见且可恢复；停止保留侧链，普通消息、新 BTW、失败或第三轮终态结束续接资格 |
| 模型与连接 | 支持内置厂商和经审核的 CLIProxyAPI 路由；会话保存型号与推理强度 | 退役型号历史可读但不可继续发送；不得静默换模或用近似 ID 冒充 |
| 上下文管理 | 有用户消息时展示当前上下文用量，回滚到空历史后隐藏入口；自动/手动压缩共享同一入口，长 turn 可在安全边界内压缩 | 工具调用与结果不能拆散；压缩不依赖摘要复述 TaskPlan、项目指令或 Skill 正文 |
| 任务计划 | 复杂目标可建立 3～7 个宏观、结果导向里程碑，并在执行中修订 | 计划服务于一个自然执行周期；正常最终正文自动结束，停止、提问或后台等待时保留 |
| 多 Agent 协商 | 支持 main-only、quick review 和 full consensus | B/C 只在讨论阶段工作，不直接修改用户项目，不把协议噪声当最终回答 |
| 子代理 | Explore、Reviewer、General 三类代理可并行完成独立子任务，父代理获得可靠终态 | 每个父会话最多 8 个并发子代理；子代理不占用户会话名额，不控制父会话或向用户提问 |
| 网页与外部工具 | 可搜索公开网页、读取与定位网页内容，并通过 MCP 延迟发现外部工具 | 外部内容一律视为不可信资料；来源应在最终结论附近可追溯 |
| 图片与截图 | 支持用户图片、桌面/窗口/区域截图、查看与裁剪；非视觉 Main 可使用视觉辅助模型 | 能力由当前连接画像 fail-closed；B/C 和协议回合不接收图片字节 |
| PDF | 支持 PDF 作为会话附件，并按模型能力读取文字或页面图 | 页面、大小、字符和派生图均有硬上限；损坏、加密或越界文件明确拒绝 |
| Office | 支持 DOCX、PPTX、XLSX 的读取、生成、模板编辑、结构检查与视觉验收 | 生成与视觉理解分离；最终文件必须经过适合该格式的确定性检查 |
| 成品交付与来源 | 最终回答下方展示可在右侧栏预览的主要成品；普通代码修改自动展示文件数与净增删行数，项目内路径相对当前工作目录展示；纯调研类回答保留来源胶囊，正文引用可定位对应来源；复制回答包含文件与来源链接 | 成品卡片打开当前版本，其它格式在正文提供文件链接；改动摘要保持当次回答的历史结果，只展示清单，不提供撤销、审核或文件点击操作。范围与契约见文档三 §3.2、§3.9；路径展示见文档二 §12.2 |
| Skills 与项目指令 | 支持项目、用户和系统 Skill；支持全局与目录级 `AGENTS.md` 规则 | Skill 不扩大权限或工具能力；项目指令与自定义 System 有不同生命周期 |
| 前端 | 提供会话历史、中央时间线、上下文指示、会话定位轨、MCP 状态查询，以及可切换任务计划/当前 Skill 的摘要区和可浏览子代理与文件版本的右侧栏 | 当前只有一套 Renderer 信息架构和视觉基线，详见文档二 §12 |
| 工作路径浏览 | 右侧栏的「+」与空栏均可打开当前工作路径；按目录浏览并在标签中预览 HTML、Markdown、代码、图片和 PDF，目录支持自动更新与手动刷新 | HTML/Markdown 可切换预览和代码；代码默认不换行，由用户按需开启；最新工具文件与目录文件共用当前文件预览和系统文件夹入口，旧版本保留快照；全屏覆盖应用内容区并保留标签栏 |
| 交互终端 | 右侧栏的「+」跟随标签列表，菜单和空栏中央均可新建终端；支持多个终端，默认进入当前会话目录，长行横向滚动查看 | 由用户直接操作，独立于 Agent 命令；关闭标签释放终端，进程与屏幕不跨应用重启恢复 |

## 4. 关键用户流程与验收结果

### 4.1 新建并执行任务

1. 用户选择项目或使用受管默认工作区。
2. 用户选择模型、推理强度与权限模式并发送首条消息。
3. 会话在首条输入写稳后立即出现在历史中；Main 在稳定上下文中执行。
4. 长任务按需建立宏观计划，可分派子代理、运行后台任务并接受用户插话；排队消息可重新编辑、丢弃或立即发送。
5. 正常结束时交付完整最终回答；需要等待用户或后台任务时保留可恢复状态。

验收要求：重新打开应用后，会话内容、模型选择、计划、附件和可恢复状态一致；不能出现跨会话串流、后台任务错归属或权限扩大。

### 4.2 修改项目

1. Agent 先读取相关文件、调用点和项目规则。
2. 文件操作使用专用工具，命令只承担命令职责。
3. 越界或需要确认的副作用通过统一审批；写入前建立适当检查点。
4. 修改后运行与风险匹配的测试、类型检查或构建，并报告真实验证边界。

验收要求：改动范围与用户目标一致；旧实现失去职责时被删除；失败不会留下半提交状态或伪造成功。

### 4.3 长任务、压缩与恢复

1. 自动压缩可在同一 turn 内触发，不能等到下一条用户消息才处理。
2. 自动与手动压缩先执行相同的可重现工具结果微清理，再按 token 预算选择安全尾部。
3. 若安全尾部仍位于同一超长 turn 内，同时生成该 turn 前缀摘要；更早历史生成常规结构化摘要。
4. 压缩、进程恢复和后台唤醒后，继续当前目标而不是重做已完成工作。

验收要求：tool call/result 始终配对；TaskPlanState、项目指令、Skill 快照和附件引用由权威状态重新注入，不依赖摘要猜测。

### 4.4 Fork 会话

1. 用户从完整模型最终回复或空闲会话命令创建 Fork。
2. 新会话复制该边界真实发送给模型的上下文和必要状态，并立即跳转；项目文件保持共享的当前状态，临时目录独立复制。
3. 源会话、源后台任务和源授权保持不变。

验收要求：两个会话的对话独立发展，Local/Worktree/managed 都共享来源工作路径，各自拥有独立临时目录。Fork 点不恢复项目文件的历史版本；所有权与删除规则见文档二 §7。

### 4.5 BTW 临时侧对话

1. 正常 Main 回复完整结束后，用户从 `/` 菜单选择 BTW；输入框与用户消息以虚线区分侧对话。
2. BTW 总是开启新的临时链；完成或被用户停止的侧轮次都可用 BBTW 续接，整条链最多三轮。停止后的模型续接能看到此前输入、已产生的回复片段和中断事实。
3. 侧对话发送后输入框恢复普通模式；用户随后选择普通消息或新的 BTW 才结束旧链。最新侧消息可原位编辑重发，保持原轮次，不额外消耗三轮额度。
4. 侧对话可调用 ReadFile、ListDir、Glob、Grep、WebSearch、WebFetch、WebFind 和只声明展示内容的 Present，沿用当前会话权限与工具设置；不额外设置侧对话工具步数或超时上限。当前模型原生支持图片时可以携带图片，不借用视觉辅助模型；输入不接受 PDF 或 Skill。

验收要求：侧问答在前端时间线和重启恢复后仍可见，但任意一轮都不得进入、改写或污染 Main 模型消息历史。

### 4.6 对话展示与模型启用选择

- 点击历史会话立即高亮目标并切换中央区域；等待超过 250 毫秒仍未就绪时，居中显示“稍等一会，马上就好”，配柔和的白光扫过效果；快速切换不闪现提示，内容就绪后立即展示。加载与历史渲染期间仍可继续选择其它会话，以最后一次点击为准；失败时恢复原会话并提示原因。
- 切换会话时输入框持续显示，与历史加载独立；立即展示目标会话的文字、附件与 Skill 草稿，没有草稿时为空，恢复完成后可编辑，各会话草稿互不串用。底部权限、协商和模型等控件在内容与可用性相同时保持外观，不因切换等待而闪烁。
- 右侧信息面板和展开侧栏在会话切换时保持外壳与宽度，内容随目标会话就绪更新；相同空状态保持原样，各会话继续保留自己的开合和标签页选择。右侧标签支持鼠标拖动和键盘排序，松手平滑归位，顺序随会话保存。
- 会话历史侧栏支持小幅拖拽调宽；两侧栏拖过最小宽度后向外继续拖动可收起，保持按住反向拖回可恢复。宽度选择跨会话和重启保留，窄窗口优先保留对话空间；尺寸与交互基线见文档二 §12.3。
- 会话支持从历史菜单弹窗重命名，也可点击顶部标题直接编辑；顶部编辑时光标位于末尾，回车或失焦保存，Esc 取消，中文输入法确认不触发保存。名称持久保留，长标题单行截断，不改变会话内容和最近活动顺序。
- Markdown 表格的复制、下载共用清晰的浮层格式菜单，支持 Markdown、CSV、TSV，并在表格工具栏反馈结果。
- 正文支持金额与数学公式混排；美元金额保留货币符号及相邻加粗、链接，公式按统一定界语法排版。语法边界见文档二 §12.2。
- 普通正文网页链接使用蓝色文字与站点图标，悬浮或键盘聚焦时显示虚线下划线；图标不可用时显示小地球。链接保留原有打开行为，不转成引用或增加来源胶囊。
- 未发送的输入按会话自动保存，切换和重启后恢复文字、图片、PDF 引用及 Skill 选择。新会话只有一个可返回的草稿入口：重复点击新建、切走再返回均保留内容与工作目录；显式选择或移除项目仍可更换草稿工作区。首次发送即登记到历史列表，工作区创建期间可从列表返回，也可点击新会话建立另一份独立草稿；创建失败保留原入口供重试或删除。草稿不进入模型上下文。
- 长会话先展示最近一段，向上接近顶部时自动补载更早内容并保持阅读位置；定位轨可跳到尚未加载的消息，同次运行内切回会话保留阅读进度。分页只影响展示，不缩减模型上下文。
- 新用户消息正式进入时间线或当前执行阶段结束后，上一批工具统一折叠，用户仍可手动展开查看；仅排队不提前折叠。
- 工具独立卡片与折叠列表共用详情展示，命令与输出可分别复制，文本结果与图片采用一致的查看方式；单文件写入可查看操作后的内容，多文件编辑和删除仍按文件展开差异。任务计划详情展示当次调用的目标、进度和任务列表，标记更新条目，完成证据按需展开；关闭和失败调用显示结果说明。
- 消息、待发送附件和预览中的图片可右键选择“复制图片”，按完整尺寸复制到系统剪贴板；左键查看原图。
- 工具详情、工具列表、代码预览和思考内容各自按纵向溢出决定滚动边界：自身有滚动内容时，到顶或到底后停在本区域；自身未溢出时，才交给最近有滚动内容的父区域。
- 工作期间的实时「已处理」始终位于输入框正上方，与当前根 turn 的文件净改动统计并列；反复修改只计最终差异，恢复原样的文件移出统计。待发送的排队消息位于这一行上方。仅增删行数使用逐位滚动动画，并遵守系统减少动态效果设置。
- 超过十二行显示高度的用户文本默认折叠，通过“展开全文 / 收起”切换；复制、编辑和发送给模型的内容始终保留全文。重新编辑时使用正文区域完整宽度，高度上限与普通消息气泡宽度不变；切换会话取消未提交的编辑。
- 最新消息重新编辑仍允许已执行命令的回合。有可回滚文件时显示“同时回滚本轮文件改动”，每次进入编辑默认不勾选；仅有未跟踪副作用时显示低饱和度红色提醒；两者都有时在选项后显示可悬浮或聚焦查看提醒的小感叹号。取消编辑不改变对话或文件，恢复或提交失败保留原对话及编辑草稿。工具内“回滚本轮”的范围规则不变。
- 附件校验、模型错误、压缩和回滚结果等提醒统一使用短暂浮动提示，不占据对话历史；真实工具执行结果与文件回滚边界仍可查看。
- CLIProxyAPI 实例暂时不公布某个已启用模型时，保留用户的勾选并标注当前不可用；当前选择的模型在目录恢复后自动恢复可用，不必重新保存设置，重启不改变启用选择。

## 5. 明确不做

- 不把 WhyCode 做成需要用户理解内部协议才能使用的 Agent 框架。
- 不因模型自述、名称相似或一次调用成功就推断未验证能力。
- 不为所有回答强制联网，也不允许在需要当前事实或可靠出处时只依赖模型记忆。
- 不把临时脚本、日志或下载中间物默认写进用户项目。
- 不让 B/C、子代理、Skill、MCP 或项目指令绕过父会话权限。
- 不以关键词、延时、模型名称或当前已看到的部分输出猜测一个模型步骤是否为最终回答。
- 不为尚未出现的需求预建浏览器、LSP、其它附件、迁移器或平行协议。
- 不提供云端账户、跨设备同步或多人协作；除非以后形成独立产品需求。
