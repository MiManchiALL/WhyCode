# WhyCode 技术栈与系统架构

> 本文是 WhyCode 当前实现的架构说明：负责模块边界、生命周期、数据流和工程约束，不记录提交历史、测试次数或开发过程。精确的模型可见消息、工具参数和持久化协议见 `03-Agent与协议契约.md`；具体类型与 schema 仍以对应代码单源为准。

## 1. 技术栈与运行形态

- **桌面宿主**：Electron，Windows 优先。
- **语言与构建**：TypeScript、Node.js 22+、pnpm monorepo、electron-vite。
- **Renderer**：React、Tailwind CSS、Radix UI、Lucide、Streamdown、KaTeX。
- **模型接入**：AI SDK 适配层加 WhyCode 自有 Provider 能力画像。
- **运行时校验**：Zod；模型、IPC、JSONL 和工具边界均 fail-closed。
- **持久化**：append-only JSONL 会话事实源；偏好、密钥和受管资源由 Desktop Main 分别管理。
- **测试**：Node 内置 `node --test`；根命令为 `pnpm test`、`pnpm typecheck`、`pnpm build`。

进程职责：

```text
Renderer (React)
  │ typed IPC
  ▼
Electron Main ── OS / filesystem / safeStorage / processes / windows
  │ host adapters
  ▼
Core ── Agent / protocol / permissions / context / session semantics
  │
  ├─ Provider APIs
  ├─ MCP / Web
  └─ Utility Process / workers for bounded heavy work
```

### 1.1 强制边界

1. `packages/core` 不依赖 Electron、DOM 或 Renderer；测试中可独立运行。
2. Renderer 不直接读取密钥、会话文件、项目文件或子进程；它只消费 Main 投影的状态与事件。
3. Main 负责 OS 能力与资源所有权，但不复制 Core 的 Agent、权限或协议判断。
4. 同一事实只有一个权威来源。UI 派生状态、缓存和摘要不能反向成为业务事实源。
5. CPU/内存明显的解析、渲染和转换不得阻塞 Electron Main；使用有界 worker 或 Utility Process。

### 1.2 开发依赖与缓存

pnpm 包 store、元数据缓存和 Electron 下载缓存使用工具默认的共享位置，仓库不覆盖路径；开发者可通过本机配置调整位置。pnpm store 应与项目处于同一磁盘卷，以便复用包文件的硬链接。

各项目保留自己的 `node_modules` 和 `node_modules/.pnpm` 依赖树；版本由 `pnpm-lock.yaml` 锁定，包管理器版本、依赖补丁与安装脚本许可仍由仓库配置管理。构建产物和 Vite 等项目缓存保留在项目内。用户配置和会话数据的存储不属于开发依赖缓存。

SSH 组件由 `scripts/build-remote.mjs` 在 Desktop 的 dev/build 前构建，开发机需要 Go 1.25+；依次使用 `WHYCODE_GO`、项目内 `.cache/toolchains/go/bin/go` 或 PATH 中的 Go。模块和编译缓存位于 `.cache/go`、`.cache/go-build`，两种 Linux 架构产物位于 `apps/desktop/resources/remote`，均不提交。源文件摘要未变化时复用产物；分发桌面应用时须携带该 resources 目录，服务器不需要编译器。

## 3. Agent 与事件生命周期

### 3.1 AgentSession

`packages/core/src/agent/session.ts` 是普通 Main 的执行入口。一个用户 turn 在开始时冻结当前连接、模型、推理强度、权限与可用工具，之后的工具续轮始终使用同一快照；用户在运行中修改设置只影响下一 turn。

Main 不设置固定总模型步骤上限。停止条件来自自然完成、用户停止、需要用户回答、后台等待、Provider/协议错误、上下文边界和通用循环健康保护。B/C 协议回合仍有协议级上限；子代理 activation 不设固定步骤数，但服从相同的取消、超时、重复调用熔断、上下文和权限边界。

模型生成与工具执行使用不同的提交边界：

1. 基于已提交活动上下文发起模型请求。
2. 流式事件只进入当前步骤缓冲。
3. 完整且可交付的模型响应先保存 canonical 调用及供应商元数据，再由宿主校验、授权、派发工具；半截模型流不执行工具。
4. `ToolExecutionBatch` 将校验、批量审批与实际派发分开，按原调用顺序执行连续只读组和独占屏障。工具进入执行函数前写稳入口，结果返回后逐个持久化，图片、PDF 和已产生的计划状态随对应结果保存。
5. 取消会停止尚未开始的调用，并等待已开始的调用收尾；已完成结果保留，未执行与结果未知明确区分。全部调用配齐结果后才注入插话或请求下一步模型。
6. 尚未执行工具的失败、取消或不可交付模型流可以丢弃；已发生的工具事实不随整步撤销，也不会因后续空响应或协议修复而重放。

相同工具及等价参数连续重复三次触发通用循环熔断。模型请求的超时与恢复由 Provider 共用入口管理，见 §4.2；长命令使用独立的命令生命周期。

日志保留真实完成次序；AgentSession、SessionJournal 与活动链恢复共用 `session/tool-execution.ts` 的局部消息投影，只重排同批工具结果。回滚锚点、压缩快照与 Fork 从规范历史派生，不另建执行日志或排序缓存。并发边界、错误分类及配对不变量见文档三 §2.3。

### 3.2 过程与最终正文

Renderer 不根据模型名、措辞、时间或“当前只看到文本”预测未来。模型步骤提交后才分类：

- 该步骤包含工具调用：正文属于执行过程，保持既有展开状态。
- 该步骤没有工具且有可交付正文：正文是最终回答，过程按统一规则收起。
- `AskUserQuestion` 是工具调用，不是最终回答；等待卡出现时执行过程保持展开。

工作阶段结束时，无论正常完成、提问等待、异常退出还是主动停止，末尾尚未封口的工具批次统一折叠成摘要。用户主动停止时，尚未提交 step 中已经显示的正文仍属于执行过程，过程保持展开。只有已经通过 `step-committed` 确认的纯文本最终回答才保持收起；不能根据中止瞬间“尚未看到工具”推测正文已经进入最终回答。手动开合属于当前进程内的视图状态，不改变 transcript。

运行中用户输入仅进入排队状态时不封口工具批次；只有消息在稳定边界正式注入、真实 user message 进入时间线后，才封口此前的末批工具。重新编辑或丢弃排队消息不会改变工具展示。原始块整理成工作分组后仍保留前方工具的封口边界。封口只改变工具批次投影，不收起整个执行过程，也不改写原始 Block 顺序。

### 3.3 Steering、停止与后台续轮

- 运行中的用户输入按真实 user message 在稳定步骤边界注入，不用关键词猜意图。
- 排队消息以稳定输入 ID 为单位操作：重新编辑会安全退回草稿，丢弃会从 canonical pending inputs 移除，立即发送复用 urgent steering；三个动作都与当前步骤注入竞争保持原子。
- 用户 Stop 终止当前 runLoop，保留已执行工具与对应状态，不自动回滚文件或继续旧任务。立即插话在同一 turn 内结清工具结果后处理最新输入；普通排队等待当前工具批次完成。
- `RunCommand` 默认在当前工具步骤前台等待；必须跨回合继续运行的进程只有显式 `runInBackground=true` 才交给宿主后台管理并投影到 Header。只有同时设置 `wakeOnCompletion=true` 的任务会在自然完成或失败后通知并续接原会话。
- 后台任务、子代理、审批和命令都以 sessionId 绑定，切换 UI 会话不会转移所有权。

### 3.4 CoreEvent 与 ViewEvent

CoreEvent 是运行时与持久化的稳定语义事件；ViewEvent 是从已提交事实派生的用户可见投影。新增事件必须同时回答：

- 是否进入模型上下文；
- 是否写入 JSONL；
- 恢复时如何重放；
- Fork/压缩/回滚是否复制；
- Renderer 是否展示；
- 中止时是否保留。

流式 delta 不应制造大量 React 长生命周期对象。Desktop 先按相邻同类事件合并并以 `requestAnimationFrame` 有界刷新；步骤提交、丢弃、工具边界和会话切换立即冲刷缓冲。

Desktop 的 `shared/conversation-state.ts` 是唯一会话视图投影，Main 与 Renderer 共用其事件归约；`ViewTimeline` 增量投影已提交历史，冷投影分批让出宿主事件循环，随运行时卸载释放。Main 保留模型恢复所需的完整 Journal，只将请求的历史窗口及当前控制状态发送到 Renderer；分页不改变 Core、JSONL 或模型上下文。窗口和游标契约见文档三 §7.1。


## 4. Provider 与模型目录

### 4.1 单一能力画像

- `packages/core/src/providers/catalog.ts` 保存内置厂商的精确模型 ID 与官方固有画像。
- `packages/core/src/providers/registry.ts` 保存厂商协议工厂，并从目录自动装配注册表；型号、顺序和能力不重复维护。
- CLIProxyAPI 的审核路由约束集中在 Desktop 的兼容目录中，并由唯一合成函数与厂商画像取安全交集。
- Renderer、Main、自动压缩和工具注册都消费同一有效画像，不各自猜测能力。

能力包括上下文/输出上限、输入模态、工具调用、结构化输出、推理展示与可选强度等。未知字段不是支持；CLI 路由不能反向开启厂商未验证能力。

标准 `/models` 只证明当前实例公布某个 ID，不证明该 ID 的完整能力。实例目录与静态审核候选求交集后才能调用；目录读取失败不得凭旧名称动态创造型号。`modelIds` 保存用户启用偏好，`modelRoutes` 保存实例当前可用路由，两者分别维护；自动刷新只更新路由，提交时以最新连接配置为准，连接已更换时丢弃旧响应。已启用但暂不可用的模型仍在设置中显示勾选与原因，不能因目录缺项删除启用偏好。

CLIProxyAPI 的 Base URL 是 API 根地址，目录请求在其后追加 `/models`。设置提示通常以 `/v1` 结尾，HTTP 404 明确提示检查 API 路径；宿主不猜测或改写用户配置的路径。

模型列表读取时同步实例目录，并发同步共用一次在途请求。当前模型已有密钥但暂不可用时，可见窗口每 15 秒重查，重新获得焦点时立即重查；模型恢复可用或组件卸载后停止。附件入口保留实际连接失败原因，不把暂不可用误报为缺少图片能力。

`config.ts` 按启用配置解析新会话首选；`runtime-model-selection.ts` 在连接保存后同步运行时，是否已登记会话决定能否重新选型，选择规则见文档三 §8。`model-connections.ts` 独立解析当前连接，并为列表之外的原选择提供名称和不可用原因。普通发送、编辑重发、手动压缩与后台交付共用 Main 的 `ensureSession`，按当前配置准备同一模型的凭据与能力，不复用已删除连接的凭据。

### 4.2 请求隔离与密钥

- 内置厂商、CLIProxyAPI 和搜索服务的密钥由 Electron `safeStorage` 分别加密；Renderer 只接收 `hasKey`。
- `config-storage.ts` 只将文件不存在视为未配置；读取、格式或任一受保护凭据解密失败均抛出不含敏感原文的 `ConfigReadError`，包括 MCP 密钥和 OAuth 状态。每次保存先重新完整读取原文件，失败则拒绝写入；启动迁移和自动设置同步也遵守这一边界。Main 仅在草稿及历史展示所需的可选模型解析中容许配置缺失，连接读取、实际请求和所有写入仍使用严格入口，读取失败通过既有浮动提示显示。配置仍位于 `~/.whycode/config.json`，`pnpm dev` 不另设存储目录。
- 同一 AgentSession 使用稳定且唯一的 `transportSessionId`，不同会话不得复用。CLIProxyAPI 映射为传输 header，官方直连可忽略；该 ID 不写入消息、摘要或可见正文。
- Provider 将各厂商流统一成 Core 事件，并负责工具调用、推理内容和 provider metadata 的后续轮次回传。

所有协议工厂通过 `providers/model-transport.ts` 的同一 fetch 包装读取网络。计时只覆盖真实请求等待和每次未完成的响应字节读取，默认连续五分钟无活动才取消单次请求；SSE 心跳、元数据和分片均在 SDK 过滤前计入。消费者处理、本地准备与工具执行不计时，响应结束或取消后释放 reader 和计时器。超时使用请求自己的取消器，不中止所属 Agent 步骤；用户停止或立即插话则取消整个步骤，包括退避等待。

`providers/model-request.ts` 统一分类模型 I/O 错误与有限重试，SDK 内部重试关闭。Main、讨论代理、子代理及 BTW 复用步骤入口，摘要和辅助识图复用同一请求策略；单步成功进入下一模型请求后才重置预算。`providers/model-request-message.ts` 在此边界提取供应商错误字段并生成简洁原因，HTML 错误页按 HTTP 状态概括，不把页面、JSON 响应或调试字段直接交给展示层；重试分类使用未截短的错误信息。重试与最终失败复用同一原因，超时保留失败阶段和空闲时长，HTTP 错误保留可用的状态码与请求 ID，不记录密钥或请求正文。重试分类、次数和提交边界见文档三 §2.2。

模型目录的新增、替换、退役和 CLIProxyAPI 路由维护必须遵守 `.agents/skills/whycode-model-catalog/SKILL.md`。

## 5. 工具、权限与检查点

### 5.1 工具注册

普通 Main 获得稳定完整的基础工具目录；工具不会按自然语言类别或 TaskPlanState 动态增删。角色、Provider 能力和宿主能力可以物理移除不适用工具：B/C、协议回合、子代理和非视觉模型各自使用明确白名单。

每个工具由以下部分组成：

- 稳定名称与 Zod 输入 schema；
- 与实现同目录的精简说明；
- 权限与副作用分类；
- Core handler 和可选 Desktop host adapter；
- 结构化成功/错误结果；
- 与模型无关的测试。

精确参数见 `03-Agent与协议契约.md` §3，代码单源为 `packages/core/src/tools/` 及各工具目录。

### 5.2 文件和命令职责

- 读取、创建、修改、删除和移动明确文件分别使用专用工具，即使目标在项目外；权限层处理越界审批。
- 已有文本优先 `EditFile`，新建或确需整文件重写才用 `WriteFile`。
- `RunCommand` 不冒充文件编辑器，也不提供文件回滚；命令产生的任意副作用必须由用户意图与权限覆盖。
- 普通 Main 的 `RunCommand` 是唯一命令入口：前台分支随当前 turn 取消且不登记后台任务；显式后台分支复用宿主命令管理器并投影到 Header，其中仅 `wakeOnCompletion=true` 的运行任务显示铃铛并登记终态续轮。子代理和讨论 Agent 只获得同名的前台 schema。
- `ListDir`、`Glob`、`Grep`、`ReadFile` 有分页、大小和并发边界；本地搜索优先 ripgrep，缺失时才使用有界回退。

### 5.3 权限

权限引擎同时检查模式、工具副作用、目标路径、当前工作区、会话 scratch 和阶段角色。审批只扩大当前被列出的精确调用，不改变基础模式，也不能越过只读硬边界。

同一模型步骤并行产生的待审批调用合并成一张精确清单；一次批准/拒绝只覆盖该清单。批准后及真正执行前再次用最新权限重查。宿主的项目副作用锁继续串行同项目跨会话的修改；单个工具批次的读取与修改顺序由 `ToolExecutionBatch` 负责。

讨论档允许 Main/B/C 读取项目并在各自 scratch 内写入或执行，禁止修改原项目、提交或产生外部副作用。子代理继承父权限后只能收窄，不能借画像、prompt 或工具参数扩大。

### 5.4 检查点

文件工具在写入前建立精确资源检查点：保存目标、旧字节和事务归属；回滚时先检测当前内容冲突，禁止覆盖用户或其它任务的新改动。同一用户轮次即使包含多个内部检查点，UI 只展示一个“回滚本轮”入口。

检查点和对话恢复是两个范围：用户可只恢复文件，也可恢复文件与会话状态。工具回滚跨越命令或其它未跟踪副作用时只允许文件恢复。`RunCommand` 不扫描整个工作区建立隐式快照。

最新消息编辑通过 Core 的 `agent/turn-edit.ts` 从本机历史与检查点投影恢复选项和副作用提醒；冷恢复预览不初始化模型或连接工作区，与提交使用同一活动回合资格检查。提交复用会话输入 reservation 和项目写锁；可选文件恢复复用 `ResourceRestoreTransaction`，先完成冲突校验、文件恢复与检查点状态写入，再提交对话换根和新输入。提交失败补偿文件与检查点；JSONL 编辑批次写入或 flush 失败恢复原日志尾部。成功后才发布编辑事件并启动模型，不用两次 IPC 拼接文件与对话恢复。

检查点 blob 同时作为文件工具历史展示的事实来源。Desktop 从 Journal 解析所属检查点目录，复用 Core `CheckpointManager` 读取历史，与 Agent 实例及模型连接解耦。Renderer 按所属会话的工具调用或所选检查点与精确路径读取有界文本；单次工具入口中的 `MoveFile` 使用目标路径的操作后版本。Core 以分块摘要判断操作后快照与当前路径状态是否一致；匹配且文件仍存在时直接转入统一的当前文件预览，否则保留操作后快照。不一致的快照提供“打开当前文件”，快照页不提供系统文件夹定位；不沿后续重命名或移动追踪文件身份。文件检查点创建或恢复后只重检活动快照页，重复点击同一历史文件也会显式重检；快照中的二进制、非普通文件和超过 512 KiB 的正文不进入 Renderer。当前文件由 Desktop 工作路径预览读取，资源边界与生命周期见 §12.5。

## 6. 上下文与指令

### 6.1 请求组成

一次普通 Main 请求由以下稳定层次组成：

1. 会话创建时冻结的 System；
2. 当前项目指令消息；
3. 当前根任务冻结的 Skill 目录；
4. 活动消息历史或 compact summary + 原始尾部；
5. 当前运行态提醒、TaskPlanState、当前 turn 子代理状态、Skill 正文和最新用户/工具内容。

动态时间、计划、权限、目录和进度不得拼进 System。精确消息顺序与缓存规则见 `03-Agent与协议契约.md` §1。

`prompts/current-date.ts` 从当前有效历史判断日期提醒是否需要追加，由 `AgentSession` 组装请求并沿既有步骤边界提交；不维护独立日期状态。刷新与恢复契约见文档三 §1.8。

### 6.2 项目指令与自定义 System

`packages/core/src/instructions/` 发现全局 `~/.whycode/AGENTS.md`，再从最近 Git 根到当前目录按层读取项目规则；每层 `AGENTS.override.md` 优先于 `AGENTS.md`。合并消息有内容哈希、总预算和 append-only 审计事件，文件变化时只保留一个活动版本。

高级用户可通过 `~/.whycode/system-prompt.json` 与正文文件为新会话选择 off/append/replace。快照只在会话第一次请求前读取一次并固化；当前会话切模型、压缩或恢复都不重读。

### 6.3 压缩

自动与手动压缩共享一个入口：

1. 对白名单内可重现工具结果执行幂等 microcompact，用稳定占位替换大结果。
2. 需要 full compact 时按 token 预算保留约 20k 的安全原始尾部；切点只能落在安全 user/assistant 边界，tool call/result 不拆。
3. 尾部已包含一个完整用户任务时，只对更早历史生成九节结构化历史摘要。
4. 尾部仍处于同一超长 turn 时，另为该 turn 前缀生成“原始请求、早期进展、后续所需上下文”摘要。
5. 重建时重新注入当前项目指令、Skill 投影和 canonical TaskPlanState。

自动压缩在同一 turn 内按压力检查点触发；不能等 turn 结束后才压缩。摘要不复述完整 Skill 或把已中断请求伪造成当前待办。实现见 `packages/core/src/context/`，摘要契约见 `03-Agent与协议契约.md` §4。

## 7. 会话、工作区与 Fork

### 7.1 会话事实源

完成工作区准备的会话有独立 append-only JSONL。恢复时先验证事件顺序和 schema，再分别重建模型活动消息、用户可见 ViewEvent、TaskPlanState、附件引用、模型选择与运行恢复事实。Renderer 缓存不是恢复来源；首次发送登记与工作区准备的衔接见 §7.2。

导航选择与冷加载分离：`SessionNavigation` 只提交最新请求的成功快照，已加载运行时可直接切换。冷加载保持单飞，中间被跳过的目标不再加载；准备完成但已非目标的运行时交还 Registry 的既有空闲卸载生命周期。新建、Fork、删除等资源事务仍遵守物化互斥，旧导航的成功或失败均不能改写新选择。

`metadata.json` 是可重建缓存，其中 `referencedModelIds` 从整份 JSONL 的型号选择派生，覆盖切换前和可 Fork 的历史引用。Main 在型号仍受支持时把被引用的原名保存到用户配置 `retiredModelLabels`，与偏好共用串行写入；删除最后一个引用会话时清掉对应名称。原名不依赖源码退役表，缓存缺失通过重读当前 schema 事实源重建，不改写会话。

手动会话名称与置顶同属 `SessionSidebarStateStore` 宿主偏好，使用同一队列原子写入 `session-sidebar.json`。列表投影优先使用手动名称；不存在手动名称时使用会话摘要标题。改名不重写 JSONL、模型消息或活动时间，准备中的会话也按已登记身份命名；删除会话同时清理偏好，保留工作区使用删除时的显示名称。IPC 见文档三 §7.5。

`ProjectStore` 在 `userData/projects.json` 保存项目 ID、显示名称、规范化目录与明确的会话归属，变更串行原子提交。添加同一实际目录只登记一次；首次发送登记会话时按选中的 Local 或 Worktree 源目录认领，Fork 继承来源归属，默认受管目录不自动登记。移除项目只删除这份组织记录，原会话进入“最近”；重新添加目录不追溯认领旧会话。删除会话同时解除项目归属。项目登记不授予目录清理权限，不改写 Core 会话与模型输入；IPC 见文档三 §7.6。

当前开发阶段 schema 可以直接升级；不添加旧事件默认值、双格式读取或迁移器。损坏或不支持的会话应明确失败，仍可由用户删除。

删除会话先在事实源写删除意图并阻止新工作，再分阶段停止运行时、释放资源和删除会话记录、临时目录及命令数据；项目目录另按 §7.2 处理。清理按目标工作区归属分派；只有会话归属不可读时才从有效外置清单查找目标引用。所有权记录缺失、损坏或不受支持时保留未验证的项目目录，继续删除会话，并通过完成事件提示保留原因，不解析或迁移旧格式。实际资源删除失败仍保留 delete-only 重试入口。较大的目录清理在后台进行，不能锁死其它会话或 Renderer；当前被删会话先切换到可用页面，完成后列表移除该项。

### 7.2 工作区模式

| 模式 | 项目/交付目录 | 会话删除 | Fork |
|---|---|---|---|
| Local | 用户选择的真实目录 | 即使为空也不删除，不提供目录清理选项 | 继续引用同一目录 |
| Worktree | WhyCode 管理的 Git worktree | 最后一个会话删除时默认保留非空目录，可明确勾选清理；保留已有分支 | 继续引用同一 worktree |
| managed | `Documents/WhyCode Workspace/<workspaceId>` | 最后一个会话删除时默认保留非空目录，可明确勾选清理 | 继续引用同一目录 |
| SSH | 已绑定服务器上的真实目录 | 保留项目，清理该会话的远端临时目录；失败与连接已删除时的边界见 §7.5 | 共享远端项目，复制独立临时目录 |

`WorkspaceLifecycle` 统一删除预览、释放引用和保留列表。共享目录不提供清理选项，并保留全部文件；引用检查同时包含 manifest、持久会话、活动运行时和未发送草稿，也保护以 Local 模式重新选中的受管目录及其父子路径。真正清理前重新检查，清理期间仅拒绝重新选择重叠路径。无引用且确实为空的受管目录自动清理，使用 `rmdir` 保证检查后新增的文件不会被递归删除。非空目录的“同时删除工作目录”默认不勾选；勾选后清理目录、所有权记录、Git worktree 登记及空的受管仓库父目录。Worktree 确认中明确说明未提交改动与未保存到分支的独有提交可能丢失，不删除已有 Git 分支。

managed 与 Worktree 的外置 manifest 保存 `sessionIds` 集合及可空 `retention {name,retainedAt}`，引用变更串行写入；`ManagedWorkspaceStore` 负责默认目录清单的校验和原子替换。最后一个引用释放且保留目录时记录会话名称和时间，重命名只改名称。清单处于保留状态时不参与启动草稿清理；启动按持久会话补齐 managed 共享引用，已有引用不能因历史缺失而自动丢弃。未发送默认目录只自动回收空目录，非空目录转为保留记录；Worktree 草稿仍沿用 Git 干净状态检查，并排除其它会话使用的路径。

设置中的保留列表只展示无关联会话的受管记录，按保留时间倒序，不收录普通本地项目；再次使用后从列表隐藏，Local 使用结束也不删除其空目录。列表按需读取清单，不轮询、不递归扫描大小，提供打开目录、元数据重命名和二次确认清理。

确认清理后立即关闭弹窗，`App` 持有的 `RetainedWorkspaceCleanup` 按工作区身份跟踪既有异步 IPC，只禁用目标行并显示清理状态；设置页卸载不取消请求，再次进入继续显示。不同目录可独立清理，请求结束后刷新列表；清理失败保留记录并复用顶部浮动提醒，允许重试。

Local、managed 和 Worktree 都拥有 `userData/scratch/<sessionId>/Main/`。协商使用同一会话树下的任务/角色目录；子代理使用 `subagents/<subagentId>/`。scratch 随恢复和后台唤醒保留，删除会话时定向清理，启动时只回收没有会话事实的孤儿。SSH 临时文件的归属见 §7.5。

未提交首条消息的新会话通过 `NewSessionStateStore` 保存唯一运行时 ID 与工作区描述符，尚未物化的默认目录或 Worktree 只保存计划。新建入口复用这份草稿，重复点击不创建目录或重置输入；项目“＋”与输入框选项目共用显式工作区选择，成功取得快照后替换工作区。Main 返回被替换的草稿身份，Renderer 使用与首次发送相同的原子移交保存文字和附件。Registry 保留可返回的草稿，其已物化目录排除在启动和退出清理之外；打开终端时只更新所属草稿，后台完成不能覆盖另一个新会话。被替换的草稿运行时与输入存储按各自所有权释放，已发送会话的输入不参与项目切换。

`WorkspaceContextBar` 按当前草稿身份加载启动模式与基线所需的 Git 信息；首次选择、切回草稿和重载使用同一读取入口。Main 从草稿工作区解析源目录，复用 `WorktreeManager` 检查仓库，不持久化仓库探测结果。切换、清空项目或离开草稿后，旧读取结果与错误失效；输入和无关界面更新不重新探测。目录选择只校验实际目录，Worktree 的基线与脏状态仍在显式选择和物化时重新校验。

首次发送在准备目录前由 `DesktopSessionRepository` 写入会话目录内的 `preparation.json`，沿用原运行时 ID 作为持久会话 ID，保存工作区计划、模型选择、创建时间和有界首条输入摘要。登记后释放新建入口，历史列表和运行事件立即使用该身份；记录不代表模型已经接收输入。物化结果先更新登记，再以同一 ID 建立 Journal；初始化失败不撤销已登记会话，用户可回到原入口重试或删除。Journal 建立后移除准备记录，重复创建不能覆盖 transcript。启动恢复只认领已完成物化的目录，不自动重发输入；登记与 Journal 共用删除标记、目录归属和清理生命周期。

### 7.3 Fork

Fork 只锚定完整、已提交且有非空最终正文的模型 turn。Core 从源会话活动父链复制当时真实模型上下文和持久状态，不用 UI 消息重建，也不让模型重新总结。

新会话具有新的 sessionId、JSONL、运行时、附件/检查点副本；Local、managed、Worktree 和 SSH 共享来源工作路径，仅 scratch 按点击 Fork 时的当前内容复制。对话锚点不决定项目文件或 scratch 的历史版本。源会话事实不变，共享项目中的后续文件修改对双方可见，并沿用宿主项目写锁与检查点冲突检测。后台命令、自动唤醒、临时审批记忆和项目 MCP 临时信任仍归来源，不转移。血缘只用于来源展示、命名和诊断，不形成共享运行时。

目录快照通过目标 `WorkspaceIO` 复制普通文件和目录，排他创建目标并拒绝链接、特殊文件；SSH 分支使用远端 scratch，资源与检查点按 POSIX 路径重定位，本地 JSONL 和附件仍由既有 Fork 事务复制。任一准备步骤失败都不切换会话，并清理已创建的分支资源。

### 7.4 BTW 侧对话

BTW 使用独立的 `btw-input` / `btw-response` canonical JSONL 事实。它们参与用户可见时间线、附件引用、Fork 文件重定位和重启恢复，但不参与 Main 活动消息、压缩或 TaskPlan。每次请求读取 Main 的稳定消息快照；BBTW 额外拼入同一侧链此前已提交的问答，停止轮次同时带入已有回复片段与标准中断标记。每条已发送侧输入占一轮，整条链最多三轮，运行结束后不修改 AgentSession 的 Main messages。

侧对话复用 Main 的 System、冻结 Skill 目录和完整工具装配，在每轮侧输入后追加临时问答提醒，以保持请求前缀稳定；具体顺序与工具边界见 `03-Agent与协议契约.md` §1.10。工具执行沿用普通对话的批次调度器、权限记忆、参数校验、取消、网络设置、附件接收与循环健康检查。每个工具步骤保留带 Provider metadata 的模型消息，随 `btw-response.toolSteps` 一次持久化；最终答复仍由同一响应的正文与推理字段保存。重放时从这些事实派生工具卡片，工具结果展示沿用统一有界截断，BBTW 请求保留完整结果。网页导入的 PDF 归当前会话附件存储管理，失败清理、Fork 重定位和会话删除复用既有机制，不能注入 Main 的活动附件上下文。

Desktop 让 BTW 与普通消息共用会话 FIFO 和运行名额；用户停止只终止当前生成并保留侧链，普通消息或新的 BTW 才切换输入语境。最新侧消息可按同一 `conversationId` 与 `turnIndex` 原位编辑重发，旧回复从活动投影移除且不增加轮次。流式事件仅借用有界时间线缓冲支持切换会话，终态由 canonical 事实统一恢复，不能再落一份 ViewEvent 副本。

已结束的 BTW 侧链只在下一条用户消息出现并确认不再续接时折叠，三轮额度用完本身不触发折叠。对话轨继续保留侧链中每轮的独立锚点：展开时定位原消息，折叠时统一定位到该侧链摘要。

### 7.5 SSH 工作区

`Main/ssh/` 持有连接、凭据、SFTP 与远端进程通道；Core 的 `WorkspaceIO` 仅抽象项目资源，注入目标平台、路径规则、文件系统和进程入口。既有文件、搜索、命令、权限与检查点继续使用同一套实现；模型请求、会话 JSONL、附件和检查点 blob 保存在本机。项目指令从远端读取，子代理继承目标 IO，宿主写锁按服务器身份与项目路径隔离。

连接使用 `ssh2` 的 SSH/SFTP 实现；本地 `node-pty` 不负责网络协议。Desktop 复用仓库已有的 Zod 校验配置与 IPC；远端 Go 组件借助 `creack/pty` 管理 Linux PTY，避免自行实现终端设备协议。服务器身份由用户名、主机、端口和主机公钥指纹组成，改显示名称不改变身份；旧会话不会跟随连接配置切换到另一台服务器。

`SshConnectionStore` 串行原子保存 `userData/ssh-connections.json`。密码或私钥口令默认只在 Main 内存中保存，选择记住后用系统 `safeStorage` 加密，重启后无需重新输入；私钥按本机路径读取，Renderer 只得到是否有凭据，不取回密码。配置损坏或解密失败拒绝覆盖。首次连接要求用户确认 SHA256 主机指纹，认证成功后才保存信任；已保存指纹不匹配时拒绝连接。编辑配置会先断开连接。

项目与会话绑定稳定服务器身份，连接 ID 只标识可增删的认证配置。每次使用工作区时，Main 按身份解析当前已验证配置并检查实际握手；删除后重新添加相同账户、主机、端口和指纹的连接，旧会话即可继续使用原目录与临时文件，无需改写历史。仅保存未经验证的配置不能恢复会话，显示名称相同也不能替代身份核验。重新添加相同身份和真实路径的项目复用原分组与会话归属，并保留自定义项目名称。

连接、清理和删除统一由 Main 判断是否需要补充密码或私钥口令。Renderer 复用连接编辑器的凭据字段，保留原来的“记住密码”选择；提交后继续原操作，取消则终止，不允许在继续清理或删除时更换服务器。认证失败保留连接配置，网络和指纹错误不触发密码重试。IPC 标记见文档三 §7.7。

服务器须提供 Linux x64/ARM64、SSH/SFTP、`/bin/sh` 和可写可执行的用户缓存目录；原子替换使用 OpenSSH 的 SFTP rename 扩展。首次连接检测架构，将静态组件按内容摘要上传到 `~/.cache/whycode-remote/host-<摘要>`，设为仅用户可执行并通过 SSH channel 启动。无需远端 Node、Python、Go、包安装、系统服务或额外监听端口。组件没有脱离连接的常驻服务；关闭连接、通道 EOF 或心跳租约到期会终止组件管理的进程组。断线使正在等待的操作报错，已发送写操作可能结果未知，不能自动重放。

连接设置提供添加、编辑、连接、远端目录选择、断开、组件清理和删除。选中的远端目录按真实路径登记到项目侧栏，沿用唯一新会话草稿流程进入项目，成功后通过设置页既有退出动画返回会话；失败保持选择界面。会话顶部按稳定服务器身份显示连接状态，通过既有事件与窗口焦点刷新，不轮询；点击未连接状态可重连，需要凭据时复用连接编辑器。

重新打开历史和消息编辑预览不必先连接。普通发送、编辑提交、文件恢复和访问远端资源时检查连接及项目目录，已有 AgentSession 也必须执行此检查；失败保留编辑内容和原对话。`SshConnections` 用同一状态表持有连接中、已连接、意外断开及清理中的生命周期。本次应用运行中成功建立的连接意外断开后，`resume` 可在下一次操作前恢复；主动断开和清理会移除恢复资格，重新启动应用也须先点击连接。清理期间阻止连接和资源使用，保留原 SFTP 仅供清理，结束后关闭；迟到的关闭或连接结果不能恢复用户已取消的连接。状态不持久化，不后台轮询，也不重放结果未知的旧操作。

文件浏览、预览与终端复用既有资源管理器和 `TerminalSessions`；远端 PTY 输入输出不进入模型上下文。远端文件变更按工具事件或用户刷新读取，不注册本机文件监听；可保存到本机，不能直接调用本机默认应用或文件夹定位。文件保存的视图归属与失败边界见文档三 §7.3。

远端临时文件位于 `~/.cache/whycode-scratch/<sessionId>/Main` 与 `subagents/<subagentId>`。准备目录时拒绝经过符号链接；删除会话复用既有分阶段删除流程，按已绑定服务器身份、规范父目录和会话 ID 清理自己的整棵临时树，内部链接只移除链接。清理后用非递归 `rmdir` 移除空的 `whycode-scratch`，保留其它会话、并发新建目录或未知文件，下次准备会话时再创建。删除确认明确保留服务器项目目录，不提供目录删除选项。

连接、路径校验或文件删除失败时保留 delete-only 记录供重试；没有匹配身份的已验证连接配置时，继续删除本地记录，完成提醒明确说明远端临时文件已保留。此时若被删会话是所属项目的最后一个会话，同时移除该空项目登记；断开、清理组件或重新建立匹配连接后仍有有效配置，不触发空项目移除。该判断不清理其它空项目。

连接设置中的三种释放动作有独立边界：断开只停止连接及其命令、终端，保留全部配置与文件；清理远端组件同时断开连接，仅删除带匹配 WhyCode 归属标记的组件文件，保留连接条目，重连时自动部署；删除连接先完成组件清理，再移除本机配置。未曾通过认证并保存信任的条目没有部署组件，可直接移除。组件不存在视为已清理，未知文件或链接则拒绝清理；连接或清理失败时保留配置供重试。三者均保留项目登记、会话记录与远端临时树。组件与会话临时文件的清理共用 SSH/SFTP 文件通道，不依赖组件启动，也不会为清理而重新部署组件。

SSH 会话及子代理通过目标 IO 使用远端 Skill、`ViewImage` 和 `ReadPdf`；文件在原权限范围内读取，本机处理器只接收校验后的字节或临时副本，不接收远端路径作为本机文件路径。实现与预算分别见 §10、§11.1 和文档三 §3。当前不提供跳板机、SSH config 导入、远端 Worktree、协商、桌面截图或 Office 工具。全局 MCP 与网页访问仍在本机运行，远端项目级 MCP 配置不会作为本机进程启动。

## 8. TaskPlan

`packages/core/src/tasks/` 维护唯一当前 `TaskPlanState`，不保存历史计划。普通 Main 始终注册 `CreateTaskPlan`、`ResumeTaskPlan`、`UpdateTaskItem`、`CloseTaskPlan`：

- 初始计划只包含 3～7 个宏观、结果导向里程碑，最后一项是唯一验证里程碑。
- 进入某项前先标记 `in_progress`，再读取相关代码并直接实施；详细操作步骤不进入计划菜单。
- `UpdateTaskItem` 负责增加、删除、修改、重排和状态推进；结构变化原子提交。
- 正常完整最终正文在同一步自动关闭计划；用户停止、等待回答、明确暂缓或等待后台/子代理终态时保留。
- 新 turn 不继承上个 turn 的 engaged 权限。需要继续时按状态 Resume；明确放弃/切换目标时 Close 后重新扫描并 Create。
- 计划工具的每个结果都携带最新 canonical TaskPlanState；压缩和恢复从权威状态重新注入。

精确字段、状态转换和 `AskUserQuestion` 续接规则见 `03-Agent与协议契约.md` §5。

`session/task-plan-view.ts` 从可见时间线投影最近展示的计划；编辑边界只读取目标 turn 起点之前的事件，并优先使用该起点的权威活动状态。实时编辑、Journal 快照与冷恢复共用此投影，不新增历史计划缓存。执行状态与展示快照的边界见文档三 §1.11。

## 9. 多 Agent

### 9.1 协商

`packages/core/src/consensus/` 实现 main-only、quick-review、full-consensus。候选和投票通过 `SubmitProtocolOutput` 合成工具提交并经动态 Zod schema 校验；Agent ID、轮次和 candidate ID 由 Orchestrator 分配。

B/C 以独立受限会话工作，拥有各自 scratch 和跨任务压缩记忆；它们不接收图片、PDF、Skill、MCP、TaskPlan 或项目写权限。协议成功提交即结束该协议 turn，普通协议正文不进入用户最终回答。最终执行仍回到 Main。

协议原文位于仓库外 `E:\Agent\multi-agent-decision-protocol.md`。修改 `core/src/consensus/` 时必须同时核对该文档与现有协议回归。

### 9.2 子代理

`packages/core/src/subagents/` 提供固定画像：

- **Explore**：只读代码、文件和公开资料，适合探索与方案调研。
- **Reviewer**：只读审查实现并可运行验证命令，适合质量和风险评估。
- **General**：可在继承权限内完成边界明确的实现或转换任务。

父会话最多并发 8 个子代理，该额度独立于用户会话运行上限。新建时同时持久化简短任务描述；每次 activation 创建独立 transcript 和 scratch，结束立即释放 AgentSession，需要继续时用稳定 subagent ID 从 transcript 冷启动。运行时不会因历史资源存在而自行续接；父模型可用 `ListSubagents` 按状态、ID 和任务描述重新发现并复用当前会话的既有子代理。

新建子代理默认冻结父会话当前模型；用户也可把子代理模型固定为任一已配置连接。宿主在创建边界同时规范化该模型支持的推理档位并写入 manifest，后续 activation 始终沿用子代理自身快照，不随父会话或全局设置变化。

子代理复用 Main 的 PDF、Office 处理器与截图调度端口，Core 完成能力装配后统一应用冻结定义的工具白名单，独立计划工具保留。具体角色和视觉工具范围见文档三 §6.2。工具附件保存到子会话目录；冷恢复使用同一 PDF 处理器校验附件，图片预览由宿主在已加载父会话范围内核对子代理归属后读取，无需重新激活 AgentSession。

子代理不能调用 `AskUserQuestion`、Fork/控制父会话或扩大权限；可以拥有自己的独立 TaskPlanState。运行时始终生成 `completed | error | aborted | limit | refusal` settlement 并通知父会话，即使子代理报错、耗尽上下文或没有主动汇报。

父 turn 以 activation 为单位跟踪本 turn 启动或继续的子代理。每个 settlement 在稳定边界立即进入同一 turn；父代理继续不重叠工作，已无工作但仍有未交付 activation 时进入事件等待，不轮询、不结束 turn，用户仍可正常插话。只有本 turn 全部 activation 终态已交付后，普通无工具正文才允许成为最终回答并结束 turn；全部交付只解除等待闸门，不会截断父任务仍需完成的工作或核验。用户 Stop 会取消本会话尚未结束的子代理；仅当本次确实取消了子代理时，父 transcript 的持久中断标记才附带其稳定 ID 与任务描述，不保留旧 turn 状态投影。

## 10. 图片、PDF 与 Office

### 10.1 图片

附件采用 staging → 校验/哈希 → commit/rollback 事务。JSONL 保存稳定引用，不保存 Base64；请求边界才读取和编码真实字节。当前用户输入支持 PNG/JPEG/WebP，单条消息最多 10 张；普通视觉工具与 MCP 单步骤最多 4 张。

视觉 Main 原生接收像素。非视觉 Main 只有配置了有效视觉辅助模型时才获得 `AnalyzeImage`；辅助模型只接收独立视觉问题和选定图片，不接收主会话历史、项目或工具。B/C 与协议回合物理移除视觉输入。

`ViewImage` 通过工作区 IO 限量读取图片，再进入本机会话的附件事务；本地与 SSH 使用相同模型能力判定。`workspace/read.ts` 以已打开句柄的元数据检查普通文件和大小，循环处理短读并检测读取期间的尺寸变化，取消或结束都关闭句柄。

### 10.2 PDF

视觉模型可把小 PDF 按页展开为内部 JPEG；更大文件显式调用 `ReadPdf` 分页读取。非视觉模型读取有界提取文字。WebFetch 命中 PDF 后进入同一附件事务，再由 `ReadPdf` 处理，不保留第二套网页 PDF 解析链路。

SSH 路径来源通过同一有界读取进入本机临时目录，由既有 PDF 处理器解析；页面附件仍归当前会话。成功、失败和取消都释放源文件与渲染临时目录。附件来源继续读取本机会话存储，不随工作区切到远端。

PDF 派生页图只作为模型输入，不自动显示在聊天中。类型、页数、文件大小、字符总量和缓存均有硬上限；详情由 `packages/core/src/pdf/limits.ts` 与 `03-Agent与协议契约.md` §3 定义。

### 10.3 Office

Office 通过 `BuildOfficeArtifact`、`InspectOffice` 和视觉模型可用的 `RenderOffice` 形成单一工作流。构建脚本在收窄的 SES 环境运行，不能访问 Node 环境；输出先进入 staging，完成适用的模板约束、公式重算与结构检查后原子发布。PPTX 模板要求经构建请求传入 Office worker，比较器只执行声明的附加约束，参数契约见文档三 §3.8。视觉复核在文件发布后、最终交付前完成，发现问题需重新构建。

非视觉模型可以创建和检查 Office 文件，但只能声明结构验收；视觉模型在最终版本上增加全页渲染复核。内置 documents/presentations/spreadsheets Skill 是工作流规范，实际 schema 以工具代码和 `03-Agent与协议契约.md` §3 为准。

## 11. Skills、Web 与 MCP

### 11.1 Skills

Skill 来源：

- 项目级：Git 根到当前目录各层 `.agents/skills/`；
- 用户级：`~/.whycode/skills/` 普通子目录；
- 系统级：`~/.whycode/skills/.system/`。

每个根任务冻结一次目录和显式选择的正文；正文只投影到请求尾部，不写成第二份长期消息。Skill 资源仍受根目录、大小、UTF-8、digest 和权限约束；Skill 只能指导现有能力，不能扩大工具、项目或审批边界。

发现、路径身份和资源读取统一使用工作区 IO。SSH 的用户目录和项目目录均来自服务器，Skill 身份同时绑定服务器与路径，不能把另一台服务器的同路径选择作为当前选择。运行时持有独立目录服务，子代理复用父运行时的目录服务；离线历史不触发连接或混入本机 Skill。每次列出或开启根任务重新发现，SFTP 秒级时间戳不能判断等长修改，远端正文用内容摘要复用有界解析缓存；当前任务仍保留冻结快照。

活动 Skill 由 `SkillTurnContext` 的当前激活集合单一持有；`AgentSession.activeSkills` 和变更事件只投影摘要，Desktop 将其传入会话运行态快照。Renderer 按运行时 ID 接收事件，切换会话或重载时以该运行时快照校准，不从历史工具卡片或输入中的 Skill 标签推断。事件边界见文档三 §1.7。

### 11.2 Web

`WebSearch` 由已配置的固定搜索后端执行；`WebFetch` 和 `WebFind` 负责确定性抓取、正文转换、分页与字面查找。所有 URL、重定向、超时、响应大小和正文长度均有宿主与 Core 双重限制。工具返回来源链接与证据信息，正文如何使用链接由稳定 System 统一约束，契约见文档三 §3.9；工具卡不把不可信网页正文当 Markdown 执行。

### 11.3 MCP

MCP 工具先以有界目录暴露，模型通过 `ToolSearch` 延迟发现并加载；实际工具仍走统一 schema、权限、取消和结果限制。项目临时信任属于当前会话，不随 Fork 转移。resources、prompts、sampling、elicitation 或 MCP Tasks 只有形成真实需求后才分别设计。

## 12. Renderer 架构与视觉基线

Renderer 代码位于 `apps/desktop/src/renderer/`，维护显示状态与用户尚未提交的输入草稿；会话、运行、任务和后台事实来自 Main 快照与事件流。

### 12.1 信息架构

- 左侧：新会话、置顶、项目与最近会话、运行像素动画和未读终态。项目标题悬浮或键盘聚焦时显示添加入口；项目行可折叠会话，并提供新建会话与管理菜单。文件夹图标只在项目行悬浮或折叠按钮获得键盘焦点时切换为箭头，鼠标点击保留的焦点不维持箭头。输入框的项目选择共用登记列表，行内名称单行省略并为操作保留空间。远端项目以“连接显示名称 / 项目名称”展示，两段各不超过名称区的一半并独立省略，悬停保留连接名称与完整路径。运行标记来自宿主 runtime 的 busy 状态；父会话终态和子代理状态变更均触发既有的合并刷新，覆盖当前与后台会话，避免子代理异步收尾后留下过期动画。
- 中央：会话 Header、时间线、执行过程、Markdown 正文、会话定位轨和一体输入框。
- 右侧：环境信息、子代理，以及可切换的任务计划/当前激活 Skill；打开详情侧栏时替换摘要区，不同时占用宽度。详情以会话独立标签组织，文件按规范化绝对路径复用标签，终端每次新建独立标签；「+」位于标签列表末尾，空栏居中提供终端和当前工作路径入口。
- 设置：通用位于首位并默认打开，其后为模型连接、辅助模型、协商模型、网页搜索、MCP、SSH 连接和保留工作区。SSH 使用服务器图标，空列表只提供中央添加入口，有连接后提供标题旁的添加入口。

设置不提供手动刷新按钮。进入分类或窗口重新获得焦点时读取最新快照，保存和 OAuth 操作直接使用返回快照；正在提交时不发起背景读取，迟到结果不能覆盖后续操作。SSH 另订阅 Main 的连接状态通知，保留工作区订阅会话删除完成并跟随清理结果更新；离开页面释放监听与未完成读取的结果，不轮询。自动读取成功不弹提示，失败复用浮动反馈。

### 12.2 字体与 Markdown

全局使用 DSH 对齐的系统 UI 字体栈。会话字号通过“通用”设置按 1 px 步进调整，范围 12–17 px、默认 14 px；`useConversationFontSize` 在应用层单一持有并通过 Renderer `localStorage` 保存，不进入会话或模型配置。设置即时更新中央 `.wc-conversation` 的 CSS 变量，作用于用户消息、模型正文及输入区；输入文字与原生 placeholder 共用字体属性，空闲、工作中等提示沿用同一输入节点。工具调用区域、文件改动摘要、Header、历史侧栏、设置 Portal 和右侧文件预览保持自身字号。改变字号不改写消息、不重建 Markdown 或重新读取文件。

`conversation-typography.css` 集中持有会话字号与 Markdown 排版，采用 DSH 的 14 px 基准；正文、标题、阅读行高和块级留白按同一比例变化，组件不散落固定正文字号。正文比例为 `q = 字号 / 14 px`，次级字号沿用 `s = min(字号 - 1 px, max(13 px, 字号 - 2 px))`，次级比例为 `r = s / 13 px`：

| 内容 | 字号 | 行高 |
| --- | --- | --- |
| 模型正文、输入文字 | 当前字号 | 24 px × q |
| 用户消息 | 当前字号 | 22 px × q |
| 一级 / 二级 / 三级标题 | 21 / 19 / 18 px × q | 30 / 28 / 26 px × q |

14 px 时正文块间距 16 px，一级至三级标题前后间距 32 / 16 px，四级至六级标题为 16 px；列表项目间隔 6 px、嵌套层间隔 4 px、缩进 18 px。表格单元格内边距 10 / 16 px，横线前后间距 32 px；这些阅读尺寸均乘以 `q`，内容列宽独立于字号。引用竖线和分隔线复用中性描边色，行内代码使用浅色背景与圆角细边。工具详情容器固定次级字号与行高，文本、文件代码与计划共用这一局部作用域；原始工具输出保留纯文本与换行，不按工具名称另设字号。文件代码分块的占位高度与实际行高共用变量。右侧预览及任务摘要仍使用原有字号与行高。唯一 `MarkdownContent` 负责：

- GFM、CJK emphasis 和安全外链；
- 流式正文的轻量展示与定稿后的完整解析；
- KaTeX 数学统一接受 `$…$`、`$$…$$`、`\(…\)` 与 `\[…\]`；正文渲染和引用投影共用 `remarkMathSyntax`，在 micromark 语法入口复用上游数学 token 与 AST 转换；
- 代码块、表格横向滚动和嵌套列表层级；
- 不改写模型原文语义，不建立针对某个模型的预处理分支。

单美元使用 [Pandoc 的定界规则](https://pandoc.org/MANUAL.html#extension-tex_math_dollars)：开符后与闭符前不能是空白，闭符后不能紧接数字；不满足时由同次 Markdown 解析保留普通文字和强调结构，避免多个美元金额被拼成公式。数字公式仍然有效，不按金额、语言或正文内容猜测语义。明确的 `\(…\)` 直接解析，不转换成单美元语法；双美元沿用上游规则。定稿仅规范化 `\[…\]` 与附着正文的块级公式，按语法树保留已有行内公式、代码、链接、HTML 和 frontmatter 的字面量，不转换转义或未闭合定界符。

`MarkdownTable` 复用 Streamdown 的表格数据提取和格式序列化，只替换操作外壳；复制与下载使用共享 Radix 菜单、表面和避让规则。菜单通过 Portal 脱离表格的横向滚动裁切，结果提示随组件定时释放；CSV/TSV 下载使用 UTF-8 BOM，临时对象地址在触发下载后释放。

未标记为显式引用的 HTTP(S) 链接由同一链接组件展示蓝色文字、站点图标和悬浮/键盘聚焦的虚线下划线，长标题保持行内换行。`SiteIcon` 使用浏览器懒加载与异步解码，固定尺寸的地球图标承接加载和失败状态。图标只通过 `whycode-site-icon` 图片协议按站点 origin 读取 `/favicon.ico`，不抓取网页或调用第三方图标服务；Main 复用网页读取的公开地址、无凭据及逐跳重定向检查，限制 5 秒、64 KiB 与图片类型，Renderer CSP 不开放任意远程图片。Main 最多缓存最近 64 个站点的图片字节（合计不超过 4 MiB），成功保留一天、缺失五分钟，取消请求不缓存失败；缓存仅在应用进程内存在，可随时丢弃，不参与会话、来源投影或模型工具。

正常完成的回答由 `WorkSection` 从同一工作分组中最近一次成功的 `Present` 结果投影成品文件；来源由最终正文中的显式引用投影。正文图标与 `ResponseFooter` 共用同一回答的来源集合，不依赖另一份工具声明。每个正文块使用与 Streamdown 同版本的 unified/remark 解析器及扩展，按语法树识别引用；代码、公式、HTML、图片与未使用的定义不产生来源。渲染插件在安全清洗后按 Markdown 节点位置标注引用链接，不放宽 HTML 属性白名单；同址普通链接保持原义，文件预览与过程正文不参与引用展示。

链接组件直接订阅来源投影，流式正文正常完成时图标与胶囊同步出现；中止不展示交付入口。无关更新保留投影对象身份，语法树在解析后释放，不保存全局来源缓存。复制与 Fork 操作属于整次回答；复制将有效引用转换为普通 Markdown 链接，保留代码示例，并附上文件链接与来源列表。文件声明与正文沿用 canonical 消息及既有回放，不增加会话字段、独立存储或第二份交付事实。模型契约见文档三 §3.9。

同一 Footer 的 `ResponseFileChanges` 从活动块保留的检查点 ID 按需读取净改动，复用 Core 的首尾版本比较；只读取对应清单与 blob，不扫描当前文件或保存另一份统计。摘要与成品声明独立，完整展示检查点返回的清单；同一文件可以同时提供成品预览与本轮差异入口，`Present` 不增删改动清单。Desktop 在历史改动读取入口按 `SessionScratchManager` 的根目录稳定分组，项目与其它交付文件在前，临时工作区文件在后，两组内保留原顺序；摘要与右侧清单共用该结果，不按路径中是否含有 scratch 字样猜测归属。默认展示三行，用户可展开余下文件；行数不可用时不推算。路径相对所属会话的当前工作目录展示，目录外保留完整路径；复用平台路径比较规则并按目录边界判断。目录部分灰色、文件名深色，悬停始终显示完整路径；只缩短显示，不改写检查点路径或增加文件读取。异步结果仅提交给原回答，卸载即失效。

改动摘要右侧的“撤销”按既有回滚锚点定位本轮工具入口，只展开对应工作段和工具组，不调用回滚校验或执行接口；已有选项与文件详情开合状态保持不变。定位复用会话滚动事务，先揭示工具列表内的目标，再将回滚入口置于对话可视区中央并转移键盘焦点；滚动空间不足时停在最近可达位置。摘要标题与工具摘要的悬浮背景覆盖整行，“撤销”和“回滚本轮”平时无按钮底色，悬停或键盘聚焦时在整行背景上叠加更深的中性底色。定位后同一个高亮标记同时点亮工具行与回滚入口，持续 3 秒；鼠标进入工具行或入口后移开，或点击该行，立即同步结束，重复定位重新计时，切换会话和卸载释放帧请求与计时器。用户主动展开工具组时立即结束其封口过渡。回滚范围、校验与确认仍由同一 `RestoreButton` 承担。

点击摘要标题在右侧栏复用单一“本轮改动”标签，文件初始全部折叠；点击摘要中的文件则展开并定位该文件。`RightPanelChanges` 与摘要共用清单读取和路径展示，只有展开文件才读取所选检查点的首尾快照；切换活动标签、隐藏侧栏或切换会话后释放内容，仅保留描述符。侧栏中的文件可独立展开，保持当前阅读位置；文件标题紧贴滚动区顶部吸附，与上方汇总栏之间不留代码透出的间隙。`FileDiff` 与工具详情共用差异、高亮和滚动组件，每处修改保留三行上下文，不相邻修改以简短分隔符区分，不提供未修改行展开控件。文件行悬停或键盘聚焦显示“在标签页中打开文件”和“在文件夹中显示”；前者复用当前文件标签并选择代码视图，后者复用有界文件视图的原生定位与释放流程。每个文件的增删统计紧随文件名，文件行预留操作区，悬停不改变布局。顶部汇总保持单行，空间不足时隐藏增删统计；文件摘要依次隐藏增删统计、文件名，放宽后恢复，避免内容溢入操作区。两者按实际分配宽度共用 CSS 容器查询；完整路径始终可通过文件行的悬浮提示和无障碍名称读取，不增加测量状态或文件读取。列表固定 13 px 字号、20 px 行高，差异沿用代码的 12 px 字号、20 px 行高。

### 12.3 交互与性能

- `usePanelLayout` 单一持有两侧宽度与布局测量，`PanelResizeHandle` 共用指针捕获和按帧更新；连续调宽暂停宽度过渡，不逐帧更新 React 会话状态或持久化，结束后一起提交发生变化的宽度。仅在开合边界同步提交 App 已有开合状态，两侧共同沿用按钮的 200ms ease-out 过渡，保持动画中的对话阅读下限；不维护第二份持久开合状态。拖拽开始将当前宽度固定为像素，过渡终点也使用投影像素，避免百分比宽度随另一侧动画重复换算；原生过渡结束或取消后恢复直接跟手，不另设动画计时器。松手、失焦、指针取消、窗口改尺寸及卸载释放监听、临时标记和帧请求，并恢复响应式宽度表达式；提前松手不截断开合动画，“减少动态效果”沿用全局规则。右侧收起尺寸与间距共用 CSS 变量，已收起侧按目标尺寸参与分配，不读取关闭动画的中间宽度。
- 会话侧栏默认 260px，可在 240–360px 间调整；两栏展开时，窄窗口临时限于窗口宽度的 30%，右侧收起后解除比例限制，仍受对话阅读下限与可用空间约束。左侧样式与拖拽共用同一宽度边界，右侧开合及窗口尺寸变化时同步更新。右侧普通文件面板默认窗口宽度的 36%，可在 20%–50% 间调整。对话阅读下限保留同一窗口内左侧最大宽度与右侧 45% 时的布局空间，并至少保留 420px；窗口不足以容纳左侧最小宽度和该下限时按可用空间缩窄。
- 指针与键盘调宽共用同一投影：主动侧优先，先缩窄另一展开侧栏；达到两栏展开时的宽度边界后，继续拖动 72px 且收起确实能扩展主动侧时，收起对侧。同一手势反向回到展开布局的宽度边界时恢复，继续反向拖动可恢复其原宽度。键盘调宽超过展开边界或请求最大宽度时也允许收起对侧。主动侧向外越过最小宽度 72px 后收起，反向到最小宽度恢复；两个方向均有缓冲，避免边界抖动。原本收起的侧栏不被重新展开，窗口改尺寸不改变开合状态。拖动收起后再打开使用最小宽度，按钮开合保留原宽度。两侧宽度全局保存，响应式限宽不覆盖偏好；全屏预览不受普通侧栏上限约束。
- React 与 React DOM 的最低版本为 19.3，使用上游对开发期 Performance Tracks 记录的释放修复，避免频繁渲染时持续保留组件属性副本。性能记录由 React 自身管理，应用不增加定时清理或强制垃圾回收；生产构建不启用这些开发期记录。上游机制见 [React #34803](https://github.com/react/react/pull/34803)。
- 页面内菜单、弹层和焦点行为由 Radix 负责；不要创建原生 select 或平行弹窗体系。共享菜单 Portal 层级高于表单弹窗，低于浮动反馈，保证弹窗内选择器可见且能接收输入。浮动反馈的交互节点注册为 Radix `DismissableLayer.Branch`，点击提示不算弹窗外部点击，也不关闭设置或其子弹窗；明确关闭和 Escape 仍由原组件处理。Dialog 未导出该接口，Desktop 直接声明已有的 `react-dismissable-layer` 依赖，不另设全局点击拦截。图片复制复用 Electron 原生上下文菜单与 `copyImageAt`，由 Main 为已加载的图片提供，沿用所属窗口生命周期，不新增剪贴板 IPC 或图片缓存。
- `ComposerActionButton` 复用 Radix AlertDialog 承载停止确认，数量直接来自当前 `SubagentState` 中的运行项，不额外查询或保存子代理状态。确认只绑定当前 runtime 与 work 起点；任务结束、运行数量归零、停止入口不可用或切换会话时作废，返回原会话也不恢复弹窗。确认后调用 App 原有停止入口，不改变 abort 协议；按钮在发送与停止之间保持同一节点，取消与 Escape 由 Radix 恢复焦点。
- 长驻信息面板与设置表单统一复用 Radix 菜单的中性表面、间距和分隔规范；长驻表单保持正确的页面语义，不伪装成会自动关闭的下拉菜单。
- `/MCP` 打开输入框上方的只读状态面板，展示服务器名称、作用域和连接状态；打开或手动刷新时读取，查看状态不额外连接服务器、不轮询，也不生成对话消息。读取边界见文档三 §3.5。
- 任务计划/当前 Skill 共用摘要区，同一会话内手动切换时标题淡入、内容用 CSS 高度与透明度短暂过渡；切换会话直接展示保存的视图，不沿用上一会话的过渡状态。Skill 显示名称、来源和单行截断说明，悬停显示路径；没有活动项时明确显示空状态。视图选择随既有会话面板偏好有界持久化，草稿落盘时转移、删除会话时清理；激活状态不持久化。
- BTW/BBTW 只在会话空闲且已有完整 Main 回复时出现在斜杠菜单；选中后输入框和对应用户气泡使用虚线，发送、退出模式或发送失败恢复遵守同一草稿事务。
- 工具卡片摘要由桌面共享层的单一格式化器按工具语义投影关键动作与目标；未知 MCP/Provider 工具只展示有界、脱敏的高优先级参数。独立卡片摘要使用上下 6 px、左右 12 px 内边距，卡片间距 8 px，字号与行高沿用 §12.2。独立卡片与折叠行共用 `ToolCallDetails`，统一命令复制、文本滚动与图片预览；外层摘要密度与批次封口时机独立于详情。两种摘要布局优先为工具名与状态图标分配空间，参数与文件名从零伸缩基准使用剩余宽度，并以自身内容宽度为上限；长参数省略，短参数及尾部信息仍紧邻名称。空间收紧时先让出增删统计，再让出文件名与参数，仅工具名自身超出可用宽度时才截断，回滚选项与确认保持可见；空间恢复后自动恢复摘要。文件路径和逐文件统计使用同一投影，成功且拥有检查点的文件详情展开时才读取快照；多文件调用保留调用摘要与逐文件详情，移动文件保留目标预览入口。
- 任务计划工具详情从该次结果中投影计划快照，与摘要区共用 `TaskPlanView`，不读取当前计划回写历史。仅解析当前计划工具的有效结果；失败不从输入推测任务已完成，历史进行中图标保持静态，证据展开状态随详情卸载释放。模型协议与持久化事实不变。
- 文件工具的历史快照、本轮改动、当前路径状态、子代理和终端共用右侧栏页面模型；每个会话至多 12 个标签，页面只持久化非终端描述符、活动标签、目录展开路径、文件的换行/预览选择及改动页的检查点与路径选择，不保存文件正文、高亮结果或滚动位置。文件正文只在活动标签中按需加载；描述符达到上限时只淘汰非终端页面。信息面板与展开侧栏的外壳跨会话常驻，共用既有宽度；导航等待期间保留已提交内容并暂停交互，目标快照成功后一次更新内容和各自开合状态，失败继续保留原会话。相同状态不重复隐藏、进入或重建标题，文件和终端仍按各自所有权切换。面板外壳只裁切开合动画，不承担滚动；标签栏和内容区各自滚动，激活标签不得带动外壳偏移。
- `RightPanelTabs` 使用 `@dnd-kit/core`、`sortable` 与 `utilities` 处理手势、键盘排序、碰撞和标签栏边缘滚动；现有 Radix 不提供排序能力。拖动层只包含标签，使用实色表面和 transform 过渡；移动只更新既有 tabs 数组，不切换活动页或重新加载正文。浮层在结束、取消或会话切换时释放，减少动态效果设置禁用落位动画。顺序沿用会话面板偏好，不增加独立持久状态。
- `FadedScrollArea`、文件差异和代码预览共用 `useScrollArea` 的滚动度量与尺寸观察，复用渐隐状态识别纵向溢出：有溢出时设置 `overscroll-behavior-y: contain`，到边界后仍停在本层；无溢出时按原生规则交给父级。内容与尺寸变化时重新测量，卸载时断开观察；没有独立滚动的差异片段不建立观察器。终端、菜单和定位轨维持各自的输入边界。
- 会话定位轨的布局空间由会话外壳持有，切换期间只卸载刻度内容，保持正文与输入框的横向位置；窄窗口仍按既有断点隐藏整个定位轨。定位轨只在真实可见刻度上响应悬浮；滚轮只在轨道活跃时改变窗口，点击使用确定性定位事务。
- 侧栏选中与中央标题立即跟随最新点击，读取会话与渲染历史共用连续的等待提示，阶段交接保持同一提示节点，直至正文就绪；显示前的延迟只经历一次。提示与输入框共用横向内容对齐规则，在正文可视区域内纵向居中，排除 Header、输入框和右侧面板，不随历史滚动偏移；导航不占用消息操作锁。Renderer 按请求身份忽略过时响应，内容与草稿归属只随成功快照提交；切换期间隐藏旧正文。`useDeferredValue` 让历史渲染可被新点击打断，当前会话的实时更新保持原优先级；离屏用户消息不强制测量布局。历史 DOM 就绪后恢复既有滚动锚点，重启默认到底部。
- 输入框外壳与编辑节点常驻，历史等待只隐藏旧正文及旧运行提示；交互问题卡覆盖普通编辑区时保留其节点。加载期间从既有会话草稿表只读投影目标内容，通过输入区外壳的 `inert` 暂停交互；底部控件仅按所属会话的实际可用性置灰，导航等待不改变其外观。全局附件拖放仍受导航锁约束。成功快照独占草稿切换与附件所有权移交；失败回到原草稿，不创建另一份可写状态。
- 上下文用量入口与会话已开始状态共用用户消息判断；新会话及回滚后没有用户消息的会话隐藏入口，重新发送后展示当前运行时计量。消息分项标为“消息与上下文”，说明其包含 Skill 目录等请求内容；展示层不扣除这些真实开销，计量口径见文档三 §1.9。
- 输入草稿由 `ComposerDraftStore` 使用 IndexedDB 按持久会话 ID 或未登记运行时 ID 异步保存；文字与图片二进制分开存储，打字不重复写入图片。PDF 保留文件/附件引用，Skill 保留选择而非激活状态。只缓存最近 32 份离开会话后的草稿预览，淘汰仅释放内存和对象 URL，切回时按需读盘；不预载所有草稿。首次恢复完成后才允许编辑，加载旧草稿不能覆盖新输入。首次发送登记时原子转移草稿及图片，删除会话或清空内容时清理对应数据。窗口关闭前通过受控的 Preload 握手等待最后一次草稿事务完成，失败则保留窗口并反馈；应用运行时在窗口关闭后的退出阶段清理。
- `ComposerSubmissions` 按发起运行时持有待确认输入及切走后继续编辑的草稿，直到宿主确认；Worktree 创建和附件准备不锁历史会话导航。创建进度与提交按钮从当前运行时的待确认输入投影，切换不转移提交归属。后台成功只释放已提交输入，失败仅恢复原会话的文字与附件；等待期间的新输入一并保留。首次提交结束前从事件或所属运行时快照取得正式会话身份，再完成草稿移交；不同新会话不共用存储键。
- 历史窗口从最近约 20 个完整工作分组开始，不为未加载内容保留 DOM 或占位高度；插话与连续 BTW 链不跨页拆开。向上进入距顶部一屏的范围时自动补载。定位轨只保留更早输入的有界文本摘要，点击后分批加载至目标。历史写入使用可中断的渲染事务，切换会话、历史改写或新的定位撤销旧请求的提交资格；补载只前插历史，实时尾部和步骤回滚快照保持一致。
- 补载与切回会话共用语义滚动锚点，内容异步改变高度时维持锚点，用户主动滚动或离开会话即释放观察。正文点击和文字选择保留目标段真实布局，不在鼠标命中处理期间重新启用内容跳过；定位轨节点索引只复用仍连接的 DOM。既有有界阅读记忆同时保存已加载窗口起点，重启仍从最近窗口开始。
- 运行态只渲染有意义的持续动画，并尊重 `prefers-reduced-motion`；静态装饰不使用逐帧 JS。
- 排队消息保持单行主摘要，重新编辑、丢弃和立即发送使用右侧紧凑图标操作；长文本必须截断，附件与 Skill 仍在同一卡片内展示。
- 实时计时与文件改动统计共用紧贴输入框的一行：计时靠左，统计及其悬浮列表相对输入框居中，排队卡片位于其上；正文中的活动摘要仅提供处理过程入口。文件统计按当前根 turn 的净变化展示，全部改回原样的文件移出汇总；统计来源与边界见文档三 §3.2。增删行数按位使用 CSS transform 过渡，文件数与其它指标不加数字动画。
- 长用户文本按实际布局高度折叠，截断处用静态渐隐与紧凑的全文切换入口提示；ResizeObserver 只负责判断是否溢出，卸载时断开。用户消息组件的身份包含运行时与消息编号，折叠和未提交的编辑状态随切换会话释放；编辑区域使用正文宽度，并与主输入框共用 CSS 内容定尺寸，在原有高度上下限内随字号与宽度变化重新排版，不逐次测量 `scrollHeight`。普通消息仍保持原有气泡宽度，原始消息文本不变。
- 恢复、删除、置顶、重命名、Fork、设置保存与刷新、MCP 登录与配置打开，以及文件的系统打开与文件夹定位等操作提醒投影到同一个浮动反馈组件，沿用超时、悬停与退出生命周期，不创建额外历史块。`ConversationFeedbackContext` 只分发 App 的反馈入口，不另存提醒状态；侧栏全屏、设置打开或弹窗来源的反馈通过同一 Portal 保持可见，提示属于 Radix 交互分支，点击不关闭弹窗。设置不另存成功或失败提示状态，已配置标记、字段说明和 MCP 当前连接诊断仍属于页面内容。文件操作失败不替换卡片说明或预览内容，切换会话或释放文件视图后忽略迟到错误；文件清单、快照和正文读取失败仍在对应内容区说明。工具失败属于工具卡片，文件回滚位置属于时间线状态。模型重试以紧凑过程行展示，工作终点区分完成、停止和失败；终态失败原因由 `work-finished` 进入工作分组，在过程折叠后仍可见。Main、子代理的重试事件随既有 ViewTimeline 持久化；BTW 重试只作实时反馈，失败终点从独立 BTW 记录恢复。
- Markdown、ViewEvent、滚动记忆、附件验证与会话列表缓存均有界；离开会话、步骤提交和组件卸载时释放短生命周期对象。

具体视觉红线见 `04-START-HERE.md` §5.2。

### 12.4 用户终端

Desktop Main 的 `TerminalSessions` 独立持有 PTY，Renderer 通过类型化 IPC 输入、调整尺寸并消费输出。终端不是 Agent 工具，其输入输出不进入 Core、JSONL、模型上下文或后台命令菜单。创建请求只接受运行时身份，工作目录由 Main 从该会话的工作区解析；待创建的 managed/Worktree 复用运行时 FIFO 物化目录，与首条消息初始化串行。

本地 Windows 使用 `node-pty` 的 ConPTY 与 PowerShell `-NoLogo -NoProfile`；SSH 使用 §7.5 的远端 PTY 适配。原生模块和 xterm.js 均在首次打开终端时加载，复用主窗口的 DOM，不创建额外 WebContents 或 WebGL 渲染器。全应用至多 8 个终端；每个终端保留 1,000 行滚动记录，未消费输出达到 128 Ki 字符时暂停 PTY，消费确认降至 32 Ki 字符后继续，避免 IPC 与渲染写入队列持续增长。

`node-pty@1.1.0` 使用 ConPTY DLL 时，输出管道关闭后仍可能保留输入管道和工作线程；`patches/node-pty@1.1.0.patch` 将两者的释放绑定到输出管道关闭。升级依赖时验证正常退出与关闭标签的资源释放，确认上游修复后移除补丁。

只有活动终端挂载 DOM 与尺寸观察器，后台屏幕在有界 xterm 缓冲内继续解析，不经过 React。PTY 与 xterm 从创建起使用一致的 500 列宽屏，侧栏开合和宽度变化只改变可见区域，不重排已有行；超出可见区域的内容横向滚动查看，高度独立适配。输入时跟随光标，纵向滚动条留在可见区域右边，横向滚动位置随标签保留。

收起侧栏、切换标签或已保存会话、Agent 空闲卸载均不结束终端；关闭标签、删除所属会话、替换不可再返回的旧草稿、窗口重载/崩溃/关闭及应用退出会释放对应进程、订阅和屏幕。首次发送登记时将终端绑定到持久会话身份，防止运行时重新加载后丢失归属。终端描述符和输出不写入磁盘，重启不会自动启动 shell。

### 12.5 工作路径与文档预览

`WorkspaceFiles` 是 Desktop Main 的文件浏览资源所有者；当前工作路径及 IO 由所属运行时的工作区描述符解析，读取待创建的草稿目录不触发物化。目录按展开层级读取，本地活动目录使用非递归文件监听更新列表，工具产生的文件系统修订和手动刷新也可触发重读；收起目录或离开目录标签即释放监听。目录链接及特殊文件不进入树的浏览链。SSH 的刷新与系统文件操作边界见 §7.5。

文件标签按规范化绝对路径复用，当前文件与历史快照共享标签及换行选择。工具文件入口明确选择代码，成品卡片明确选择预览，即使标签已打开也按入口更新；目录入口和普通标签切换保留已有选择。HTML、Markdown 与 SVG 在文本大小上限内提供预览/代码切换；普通文本直接使用带行号的代码组件，其它图片与 PDF 仅提供预览。当前文件提供刷新和保存到本机，本地文件另提供文件夹定位；换行按钮仅出现在代码状态。窄侧栏将当前文件的模式和操作收进同一个 Radix 菜单，与宽栏按钮共享动作和状态，不挤出工具栏。旧快照只展示当时的代码与换行按钮、快照标记，当前版本不匹配时提供打开当前文件；不提供渲染预览、刷新或定位。

代码默认不自动换行。语法解析、分词与高亮片段的转义在按需创建的共享 Web Worker 中执行，界面先显示纯文本，收到结果后以低优先级更新颜色。代码正文使用静态标记，保留完整源码、行号与文本选择，不为每个高亮片段创建 React 节点；滚动和换行复用正文节点。离屏布局按每 64 行一组跳过，避免逐行隔离与固定行号叠加导致大量图层合成。关闭最后一个代码视图时终止 Worker 并释放语法与未完成请求。工具详情的换行选择随组件卸载释放，右侧栏选择随标签保留，关闭标签后重新打开恢复默认。终端的固定列宽行为不变；超出预览大小或不支持的类型仍可保存到本机，本地文件另提供默认应用打开与系统文件夹定位入口。

开发模式的 `optimizeDeps.entries` 同时扫描 Renderer HTML 与高亮 Worker 入口，使按需模块的第三方依赖在启动时完成预构建，避免首次展开代码触发整页刷新。扫描只准备开发缓存，Worker 与语言语法仍按可见代码按需加载，不改变生产打包或运行时释放边界。

HTML 使用具有临时访问凭证的 `whycode-preview` 地址与仅允许脚本的 sandbox iframe，保留目录内相对脚本、样式、图片、字体等静态资源解析；iframe 没有 Node、Preload 或宿主 IPC 能力。PDF.js 在首次打开 PDF 时延迟加载；Worker 与字体、字符映射、解码器均为独立构建资源，二进制按需读取，不把全部资源内嵌为常驻字符串。PDF 通过协议字节范围按需读取，不预先传递整份文件；画布只覆盖阅读器视口附近的页面，每页最多约 4 百万像素且长边不超过 4096 像素。渲染完成即释放页面解码缓存，离开后取消渲染并释放画布。图片直接使用浏览器解码，不创建额外 BrowserWindow 或常驻 WebContents。

已打开文档通过 Main 的 `WorkspaceFileWatch` 只监听正文及实际读取的静态依赖，每份文档最多监听 128 个文件，按父目录复用非递归监听。事件经文件版本校验后才提示变化，无关文件活动和会话修订不标记正文过期；手动刷新与预览/代码切换共用重新读取入口，清除旧依赖并建立新文档版本；仅成功读取清除已确认的更新提示，读取期间的新变化继续保留提示。监听本身不自动刷新，避免覆盖 HTML 交互状态或打断阅读。隐藏侧栏、切换活动标签或提交新会话后撤销旧预览地址、监听、请求和 PDF Worker；后台只保留标签描述符，重新显示时读取文件当前版本。窗口重载、崩溃、关闭及所属运行时释放也撤销 Main 资源。全屏是同一面板覆盖应用客户区，保留标签栏和当前文档节点；不触发预览重建、不改变普通侧栏宽度偏好，退出后恢复原布局。

交付文件卡片默认使用白色表面、悬停使用中性灰色，只展示路径元数据，不预载文件。用户点击后进入同一当前文件标签的预览状态；保存到本机、默认应用打开或文件夹定位仅在点击时借用所属窗口的文件视图，操作完成、失败或切换会话取消后释放，迟到响应不能触发旧会话操作。

文件浏览是用户界面能力，不调用 Agent 工具，不进入模型上下文或会话历史。IPC、文件大小和路径限制的单源见文档三 §7.3。

## 13. 工程约束与验证

1. 对稳定协议先改 Core 类型和契约测试，再改 Main/Renderer 消费者。
2. 不在 UI、IPC、Provider 与持久化层复制同一业务判断。
3. 所有异步资源都要有 sessionId 所有权、取消路径和终态；切换会话不能靠组件是否挂载决定后台生命周期。
4. 任何缓存必须可丢弃、有容量上限，且不能改变正确性。
5. 测试与改动风险匹配：至少运行受影响包测试；跨层协议、会话、Provider 或 UI 基线变更还需全仓 typecheck 和生产 build。
6. 验证报告区分自动化、离线适配器、真实端点和客户端人工验收，不能互相冒充。

项目仍处于开发阶段。当前待办、阻塞和尚未完成的验证只写入 `05-暂存区便签.md`；已经完成的变更从本文删除历史叙述，只保留仍成立的架构事实。
