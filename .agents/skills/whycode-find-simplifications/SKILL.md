# Find Simplifications

调查用户指定的范围。只有请求明确指向整个项目时才覆盖整个仓库；未明确范围时，只调查用户当前指向的模块或变更，仍无法确定时说明并停止。
这是只读调查与提案任务，不修改代码。候选的实施交给 `whycode-simplify`，并按用户选定的范围分批完成。

## 调查流程

1. 读取适用的项目约束、架构说明和公共契约，明确主要入口、模块边界、生产代码范围和已有职责。
2. 搜索语言与运行时内置能力、仓库已有依赖、工具和相邻模式，识别重复实现、镜像状态、无生产消费者的表面、手写替代、泄漏抽象和不必要的兼容层。
3. 对每个候选检查生产消费者、动态注册、配置与序列化入口、字符串协议、公共契约、测试和文档；区分生产使用与仅测试或文档引用。静态搜索没有结果或仅有测试与文档引用，都不能单独决定删除或保留。
4. 对状态和异步机制确认所有权与生命周期，只在多个机制表达同一事实时建议合并。
5. 评估净收益，包括可删除表面、残余胶水、行为损失、迁移成本、接口影响和验证成本。拒绝把产品取舍或有明确理由的复杂性伪装成清理。
6. 完成约定范围的调查，不在首个候选后停止。候选过多时，只保留收益、证据强度和可实施性最高的一组。

## 输出结果

每个候选说明：

- 建议删除、合并、复用或降级的具体表面；
- 生产消费者、动态入口和契约证据；
- 预期净收益；
- 可能失去的行为及风险；
- 实施范围和必要验证。

按收益、风险和证据强度排序，区分：

- 可直接交给 `whycode-simplify` 的低风险清理；
- 需要产品或接口决策的设计变化。

仅在某个看似可删的复杂性很容易被误判时，简要说明保留理由。没有可靠候选时明确说明，不为形成报告而制造建议。
