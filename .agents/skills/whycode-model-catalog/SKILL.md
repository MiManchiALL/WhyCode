# WhyCode 模型目录维护

遵守 `docs/04-START-HERE.md`。普通型号更新应主要改变目录数据；研究、实现和测试按实际差异展开，不能把每次换代都做成完整接入工程。

## 1. 先确定最短实施路径

用一段话确定型号的新增、保留、替换或退役，连接范围，以及默认选择是否变化。沿用本次对话已有授权，不重复确认。未要求改变默认时保留原顺序和用户选择。

内置厂商是默认范围。CLIProxyAPI 只处理用户明确要求的 OpenAI、Anthropic、Gemini 型号；其它厂商不随之接入。仅删除指向退役画像的旧 CLI 项不等于获准添加替代路由。内置与 CLI 分别交付有效画像，可以并行查证，厂商契约只查一次。

先批量搜索旧、新内部 ID、wire ID 和展示名，查看当前实现、相关测试及最近一次更新提交，再选择路径：

| 变更 | 实施范围 | 测试处理 |
|---|---|---|
| 只有型号、能力数值或路由数据变化，现有 SDK 能表达 | 改目录、注册项及已授权路由 | 更新现有数据用例；通常不新增测试函数或文件 |
| 输入模态、推理闭集、签名或请求字段有差异 | 先检查当前协议工厂和请求测试是否已覆盖 | 只补缺失的协议行为断言，放进现有套件 |
| SDK 确实丢字段或不支持新能力 | 核对锁定版本源码与上游修复，优先更新现有依赖 | 保留能复现该问题的通用回归测试；不另造同协议适配器 |

不要为了普通目录更新重新通读全仓、重查无关厂商或遍历全部 Agent 项目。只有协议实现决策发生变化时，才按入口规则研究相应参考实现。

## 2. 查清差异后再写画像

以当前官方模型页和参数文档为准，记录链接与日期。每个新型号必须确认精确 API ID、展示名、稳定/实验及弃用状态、协议、输入输出模态、流式与工具、结构化输出、缓存、上下文与最大输出、其它请求硬限制、推理闭集及默认、工具续轮所需 metadata。

证据用紧凑表记录在任务工作区：`型号/连接 | 相对现有画像的差异 | 一手来源/版本 | SDK 能否表达`。官方明确适用且未变化的协议契约可引用已有依据；新型号的数值、档位和能力不能仅凭旧型号或名称继承。只有逐字段等价才复用画像常量。

直接打开权威页面；搜索结果缺失或疑似缓存过期时，核对官方目录或仓库 API，不反复扩大搜索。现有 SDK 工厂和请求测试已覆盖的链路不重新造烟测框架。缺失字段保持关闭或省略；无法确认型号身份时不接入。

仅在新增或改变 CLI 路由时读取 [CLIProxyAPI 审核指引](references/cliproxyapi.md)。源码只补查本次变化涉及的目录、转换器和默认值；证据失效或路由歧义时再扩大审查。

## 3. 在现有职责内修改

以下路径均相对仓库根目录：

| 位置 | 修改边界 |
|---|---|
| `packages/core/src/providers/catalog.ts` | 官方身份、能力和该型号唯一的 `providerOptions` |
| `packages/core/src/providers/registry.ts` | 注册项与协议工厂；换代更新注册项，工厂不随型号复制 |
| `packages/core/src/providers/reasoning-effort.ts` | 只有协议字段翻译变化时才改 |
| `apps/desktop/src/main/cli-proxy-models.ts` | 精确审核路由及相对官方画像的最小约束 |
| `apps/desktop/src/main/cli-proxy-discovery.ts` | 鉴权实例目录求交集；普通新增路由不改发现流程 |
| `apps/desktop/src/main/model-connections.ts`、`model-settings.ts` | 目录的消费者；普通型号变动应自动反映到设置、视觉辅助与协商候选 |
| `apps/desktop/src/main/config-storage.ts`、`retired-model-labels.ts` | 配置及引用型历史元数据；不能按每代型号增加分支或常量 |

模型选择与推理选择共同决定有效画像。切换模型回到 `default`，恢复及发送时把不在新闭集的旧档位归一到默认；`default` 不覆盖连接默认。UI 只展示该画像允许的档位，没有可验证档位时灰显默认。Responses、Chat、Anthropic 的现有字段翻译分别复用 `reasoning.effort`、`reasoning_effort`、adaptive thinking + `output_config.effort`。

不要向 Main、UI 或测试工具新增能力事实源，不留跨版本别名、隐藏回退、第二套 `providerOptions` 或失去使用方的适配代码。图片、工具和推理 metadata 必须经现有规范消息链路完整回传。

## 4. 退役同时删除实现和专属测试

“保留”只增加当前仍受支持的画像及必要数据用例，不复制整套测试。“替换/退役”同时删除旧目录项、注册项、路由、默认及辅助选择中的失效引用、专属参数、无使用方依赖、测试夹具和过时说明。源码和长期测试不维护真实退役型号名单；Git 历史无需改写。

历史例外只属于用户数据：

- 当前可恢复 schema 的既有会话保留其真实型号、消息、附件和必要显示信息，不重写 JSONL、不自动换型。选中退役型号时保留原名及红色“已停止支持”，可选目录不伪造旧选项，发送前要求用户主动选择当前可用型号。
- 显示信息由会话记录或受真实引用约束的最小用户元数据提供，不能从不断增长的源码退役名称表获取。不得为保持旧名称新增逐型号迁移、旧 schema 分支或双读。
- 用户切换型号不抹除已发生的对话事实。删除会话通过既有统一删除链路清理其 JSONL、附件、缓存、会话产物及专属元数据；最后一个引用消失后清掉共享退役条目，不影响其它会话、仍使用的连接或用户项目文件。

当前实现已从 JSONL 派生 `metadata.referencedModelIds`，并在型号仍受支持时将被引用的原名保存到用户配置 `retiredModelLabels`；新建、选择及删除复用同一同步链，Fork 引用取自实际复制的历史。普通目录更新直接复用此机制，不增加型号常量、会话 schema 或兼容层。移除旧型号前确认既有名称已保存在用户元数据；若发现缺口，先保全真实名称并修复通用生命周期，不能猜名或继续补源码名单。

## 5. 测试按契约复用，随型号清理

优先修改现有用例。新增长期测试前说明它能抓住什么现有测试无法发现的失败；仅确认这次 ID 改名、端点暂时可用或重复抄录能力对象，不足以新增测试。

| 测试类别 | 长期维护方式 | 型号退役时 |
|---|---|---|
| 当前目录、精确 ID、特殊能力及自动压缩边界 | 在负责该事实的现有目录或路由测试集中维护小型数据表；保留独立的预期值 | 替换或删除旧行，不追加每代专属 `it` |
| 设置、默认选择、辅助视觉、协商和配置恢复 | 用少量当前型号检查连接选择与过滤行为，不在每个消费者复制完整型号清单 | 更新受影响夹具，不为新型号复制相同流程 |
| 请求格式、图片传输、工具和推理回传 | 按实际协议行为组织，共享请求捕获设施，选当前型号作代表 | 仍被使用的协议测试换代表型号；完全无人使用的分支和测试一起删 |
| 退役显示、发送拦截与引用清理 | 使用固定合成 ID（如 `test:retired-model`），验证有其它引用和最后引用删除两种情况 | 不新增真实退役型号的负例或永久名单 |
| 真实端点烟测及单次调研脚本 | 放临时工作区，记录结果与限制，不提交临时脚本、响应或凭据 | 收尾清理，不进入常驻测试集 |

遍历目录可验证唯一性、装配一致性、闭集与收窄不变量；不能把生产目录的同一个值当成外部契约的期望值，制造必过测试。保留能发现 SDK 丢图片、漏签名或错误默认值的回归断言，不因代表型号退役而丢掉仍在使用的协议保障。

收尾搜索真实旧 ID、wire ID、展示名和无使用方常量；逐项清理当前源码、长期测试及正式说明。测试代码量应随当前能力与有效模型数量变化，不随历史更新次数增长。若普通替换仍触及大量测试文件，检查是否重复维护完整目录快照，优先收敛重复断言，不用全局替换掩盖问题。

## 6. 验证一次有效结果

以当前 `package.json` 命令及 `docs/02-技术栈与架构.md` §13 为准；测试运行器是 Node 内置 `node --test`。

- 型号/路由数据改动：运行受影响包的既有测试，以及全仓 `pnpm typecheck`、`pnpm build`。Core 和 Desktop 均受影响时直接执行一次 `pnpm test`。
- SDK、共享协议或生命周期变化：可先用 `node --test` 加明确文件路径定位问题，收尾执行全仓测试、类型检查和构建；依赖变化另跑 `pnpm audit --prod`，不新增无依据的安全例外。
- 仅维护本 Skill 或说明文字：检查 Skill 格式、引用及 `git diff --check`，不新增应用测试、不运行应用全仓回归。

通过且代码未再变化的结果直接复用，不依次重复跑文件、包和全仓的相同覆盖。出现新修改或失败才补跑受影响检查。Windows 测试断言完成但进程不退出时，先检查测试子进程回收与执行权限；不要无限等待，也不要用强制退出掩盖失败。

真实烟测先确认端点可达和型号可用，复用应用工厂与实际参数，关闭自动重试。每个变更连接用一个最小流式工具闭环尽量覆盖本次新增能力；纯换代不做全档位、全工具或长上下文压测。明确不可用时记录原因并继续其它检查，连接状态未变不反复重试。

最后检查 diff 中新增代码是否都服务于当前契约、旧型号及临时资产是否清干净、有无疑似密钥字面量。按入口规则更新所属文档和中文提交；交付说明区分自动化、离线请求捕获、真实调用及未测项。`05` 只留未解决事项，完成记录留在 Git，不新增永久模型更新日志。
