# Simplify

直接清理当前任务相关的代码。优先检查完整 diff；没有 diff 时，只检查本次任务已编辑、用户明确指定或已选定的简化候选。没有可确定范围时说明现状并停止。
这是当前任务内、行为保持的实现清理，不扩展为全项目审计、架构提案或无关重构。若简化必须改变需求、公共行为或已约定接口，只说明原因，不实施。

## 清理流程

1. 读取项目约束和完整 diff，明确改动意图、公共契约与必须保持的行为。
2. 搜索语言或运行时内置能力、仓库已有依赖、工具、类型和相邻模式，优先复用。只有项目策略允许、语义覆盖完整且确实减少净复杂度时，才新增依赖。
3. 删除或合并代码前，确认生产调用点、动态注册、配置与序列化入口、字符串协议和公开契约；静态搜索没有结果不能单独证明代码未被使用。
4. 清理重复或近似复制的实现、可派生却重复保存的状态、绕过根因的标志位、过度参数传递、泄漏的内部细节和重复工作。删除仅复述实现、记录修改过程或已经失效的注释；保留解释非显然约束、所有权和设计原因的注释。
5. 保留跨越不可信输入或所有权转移边界所需的验证、复制和隔离。对异步与生命周期代码，只合并表达同一事实的机制；不要误删分别负责取消、回滚、终态仲裁、重入保护或完整释放的逻辑。
6. 只做收益明确的修改，不为单次使用新增抽象，不做无关格式化。运行最贴近改动的测试和类型检查；相关时验证真实入口、外部行为和资源清理结果。

最后简要列出实际清理项和验证结果。没有可靠简化时明确说明，不为制造改动而修改。
